# C16-A 일봉 위치·미니차트 연결

개발 폴더에서만 구현했다. stock1-live, Collector, Telegram 설정은 변경하지 않았고 API 호출·주문·배포·commit/push 없음.

## 재사용

- `krx_c14.read_inputs/make_card`: SQLite read-only, 수집 시각/분석 시각 필터, KRX→기존 C14 카드 계약.
- `analyst.observed_daily/chart/card`: MA5/20/60, 거래량 상위 일봉 OHLC 추정 영역, 252거래일 고점 계약.
- `analyst.mini_chart`: C14-J 60봉 PNG, MA 계산용 최대119봉, 거래량, 장대양봉 종가→다음 관측 음봉 윗꼬리 고가의 구조형 저항. 수정주가/거래일 연속성 미검증 표시 유지.
- `eligibility_dashboard` 및 `top5_dashboard`: 기존 대시보드와 카드 UI를 재사용. 별도 대시보드 엔진을 만들지 않았다.

## 연결·보완

`c16_bridge.py`는 기존 C15 섹터 TOP3×대표 TOP3 순서를 그대로 사용한다. 종목코드로 저장 일봉을 연결하고 카드 JSON/관찰 텍스트/PNG 및 기존 대시보드 형식의 HTML을 출력한다. 동일 종목이 복수 섹터에 나오면 차트는 재사용하고 섹터별 카드 위치를 유지한다.

추가한 값은 최근 피벗 고저점, 장대양봉 종가·고가, 윗꼬리 영역, 가장 가까운 상단/하단 후보, 종가 대비 거리, 일봉 관찰 유형이다. 지지는 양옆 관측 봉으로 확인한 저점~몸통 하단 영역을 최대0.75% 폭으로 제한한 잠정 추정이다. 기존 계산형 저항을 유지하고 불명확하면 관측 피벗/윗꼬리 후보에 계산 밴드를 쓴다. 기존 카드 resistance 데이터와 resistance_estimate 값은 변경하지 않는다. 현 코드에는 별도 resistance_estimate 스칼라가 없고 기존 resistance.analysis/계산 영역이 해당 근거다.

분류는 초기 관찰 가설이다: 60봉/MA 부족→데이터 부족, MA20 아래이면서 MA20 하락→추세 약화, 상단 후보 2% 이내→저항 근접·추격 주의, MA20 위 3% 이내→눌림 관찰, MA20 이상·MA20≥MA60→돌파 관찰, 나머지→추세 약화. 우선순위와 숫자는 JSON의 rules에 기록한다. 돌파 관찰은 실제 돌파 확정이 아니다. 점수화·자동 주문은 없다.

미니 PNG에는 최근60봉 최고가/날짜, 최근 저장 종가, MA·거래량, 반투명 저항/지지, 가장 가까운 상단 후보 점선을 표시한다. 구조형 저항의 두 봉 날짜와 지지 피벗 날짜가 보이며, 계산형 근거 날짜는 카드 mini_chart_metadata.resistance_evidence_dates 및 원본 resistance.analysis에 남긴다.

가격대별 체결량 원자료는 이 연결 경로에서 확보되지 않았다. 일봉 총거래량을 OHLC 대표가격에 연결한 기존 추정이며 **실제 가격대별 거래량·잔존 매물·호가 유동성으로 표시하지 않는다**. 현재가는 임의 추정하지 않고 장중 현재가 미확인과 저장 일봉 종가를 구분한다.

출력: `diagnostics/c16-a-20261106-final/`

- `dashboard.html`: 기존 적격성 대시보드에 9개 주도주 카드와 클릭 가능한 PNG 연결.
- `top5.json`: 기존 카드 목록 계약 재사용, selection_source=C15. 기본 C12 Top5 표시 개수는 변경하지 않고 이 연결만 9개 표시.
- `128940/mini.png`, `316140/mini.png`, `010060/mini.png`: 대표 검증 3개. 나머지 6개도 같은 경로 규칙.
- 종목별 `card.json`, `observed.json`, `input.json`: 날짜·원본 근거·관찰 유형·저항/지지·거리.
- `summary.txt`: 9종목 요약.

재생 명령:

```powershell
.venv/Scripts/python.exe -m kiwoom_collector.c16_bridge --briefing diagnostics/c15-12-20261105/reports/c15-20261105-0950/diagnostics.json --daily-db diagnostics/lightweight-20261105/daily-120.db --as-of 2026-11-06T09:40:00+09:00 --output diagnostics/c16-new-output
```

새 개발 diagnostics 디렉터리만 허용한다. 휴대용 telegram.json을 입력하면 옆의 전체 diagnostics.json을 사용한다. 수집/전송 모듈을 호출하지 않는다.

## 검증과 최소 다음 작업

관련 29개 테스트 통과: 신규 위치/시간/9카드 실제 출력 4개, 기존 mini_chart/Top5 대시보드/KRX C14 25개. 개발 Python에는 websocket이 없어 기존 Top5 테스트 import가 실패했으며, 이미 설치된 기존 Python 3.11 환경으로 실행해 통과했다. 패키지 추가 설치나 운영 파일 수정 없음. 대표 PNG 3개를 직접 확인했고 9개 모두60봉이다. HTML 연결은 기존 렌더러 회귀와 실제9개 카드/PNG 경로로 검증했으며 브라우저 실행 화면 검증은 하지 않았다.

C16-B 최소 범위: 현재 자료와 장기 KRX 이력을 읽기 전용으로 함께 연결해 252일 고점 보강, 계산형/피벗 후보의 존 폭·분류 임계값 검토, 실제 대시보드 브라우저 화면 검증. 실제 가격대별 체결량이 별도로 확보되기 전까지 OHLCV 추정을 실제 매물대로 승격하지 않는다. 운영 연결·배포는 별도 범위다.
