# Bubble Radar 장중 타임라인

[공통 분석 정책](RADAR_ANALYSIS_POLICY.md)에 따라 TOP20 군집·지속성으로 섹터를 탐지하고 종목 TOP5 출현은 매매 후보 검토 근거로 구분한다. 선택 시점까지의 성공 관측만 사용하며 기존 TOP20 진입/유지/이탈을 TOP5 전용 상태로 바꾸지 않는다. 거래대금 미검증 시 후보 확정을 보류하며 이번 정책 보완은 타임라인 코드를 변경하지 않는다.

기준 0686a58의 v2·v3·Bubble v1을 수정하지 않고 `kiwoom_collector.bubble_timeline`에 시간 선택 출력을 추가했다.

```powershell
python -B -m kiwoom_collector.bubble_timeline --date 2026-10-20 --environment mock --db data/stock1.db --output data/bubble-timeline-20261020-new.html
python -B -m kiwoom_collector.bubble_timeline --date 2026-10-26 --environment mock --db data/stock1.db --output data/bubble-timeline-20261026-new.html
```

기본 날짜는 KST 오늘, 환경은 mock이다. 날짜·환경·ka00198·qry_tp=1·test_mode=0·성공 상태의 실제 관측만 시간순으로 표시하고 최신 성공 관측을 기본 선택한다. 다른 유형과 테스트 회차를 켜는 옵션은 없다. 기존 파일과 심볼릭 링크는 덮어쓰지 않는다. 데이터가 없으면 빈 상태를 표시한다.

## 계산과 보존

운영 DB를 mode=ro + query_only + 읽기 트랜잭션으로 열고 SQLite Backup API로 WAL을 포함한 일관된 임시 스냅샷을 만든다. 기존 radar_report 로더와 v3.analyze, Bubble v1의 모델·SVG·상세·전체 HTML을 재사용한다. 수집·API·OAuth·Store·운영 마이그레이션은 실행하지 않는다.

각 프레임은 선택 회차까지의 정확한 성공 회차 prefix만 포함한다. 같은 수집시각은 rowid 순이며 시간 라벨에 '같은 시각 1/2'처럼 구별한다. timestamp만으로 잘라 동시각의 나중 회차를 먼저 포함하지 않는다. 직전 성공과의 실제 간격은 0분·10분·60분·누락 후 120분 등을 그대로 표시한다. 실패·running·기록 없는 예정 슬롯을 가짜 정상 관측으로 채우지 않는다.

TOP20/TOP5 수·증감·출현 횟수·관측 연속·진입/유지/이탈·시세와 거래대금 상태를 같은 prefix로 계산한다. 최초 관측의 변화량과 진입은 비교 불가다. 출현 분모는 선택 시점까지 관측한 성공 회차 수다. 미래 회차의 섹터·종목·출현 횟수는 그 프레임의 분석에 포함하지 않는다. 예정 슬롯 상태도 선택 시각까지의 관측 범위로 표시한다.

현재 태그를 같은 보고서의 과거 순위에 적용하며 당시 분류 이력을 재현하지 않는다. 복수 태그는 섹터 내 1회, 전체는 코드로 중복 제거한다. 미분류는 지도 밖에 유지한다. 현재 0인 이탈 섹터는 원 없이 목록에 남는다. 등락률·금액은 기존 v2/v3의 동일 회차·최신 배치·날짜·시점·필드·단위·커버리지 규칙을 유지하고 다른 회차/날짜로 보충하지 않는다. 모의는 실전 검증이 아니며 조회 관심도 색상은 가격 등락률이 아니다.

## 화면 전환과 배치

생성할 때 모든 회차의 HTML을 계산하고, 로컬 srcdoc iframe으로 프레임을 분리한다. 상단 네이티브 radio와 CSS :has()가 선택 프레임 하나만 표시한다. JavaScript·외부 서버·CDN·네트워크 요청이 없다. 프레임마다 별도 문서여서 섹터 선택·표·검증 상세가 다른 회차 DOM과 섞이지 않는다. 회차를 다시 방문하면 그 회차에서 선택했던 섹터/보기 상태는 유지되며 데이터는 해당 회차 자료다. 다른 회차에서 같은 섹터 선택을 자동 복사하지 않는다.

Bubble 클릭/터치/키보드 상세, 버블/표/함께 보기, 미분류·신규·이탈·반복·v3 전체 진단은 유지한다. 각 프레임에서 선택한 회차와 직전 관측, 시세 상태가 함께 바뀐다. 최상단은 날짜·환경·조회 유형·운영 구분을 표시한다. 시간 바는 좁은 화면에서 줄바꿈하여 최신 선택 항목도 숨지 않는다. 본문 프레임은 자체 세로 스크롤을 사용해 긴 모바일 지도와 v3 표를 볼 수 있다.

하루 프레임 전체에 같은 반지름 축척을 적용해 같은 종목 수는 회차 사이에서도 같은 원 면적을 갖는다. 축척 설정에 당일 표시 최대값을 사용하지만 각 프레임의 수치·색상·지속성은 prefix만 사용한다. 계속 지도에 남는 섹터는 기존 셀을 유지한다. 이탈한 셀만 새 섹터가 사용하며 재등장 시 기존 셀이 비어 있으면 재사용한다. 표시 상한 8개를 넘나들거나 재등장 셀이 이미 점유되면 일부 이동할 수 있다. PC 4열×2행, 모바일 2열×4행의 고정 셀이므로 빈 셀 공간은 남지만 원은 겹치지 않는다.

회차 전환은 120ms의 짧은 투명도 효과만 사용한다. 좌표·면적을 중간 값으로 보간하지 않는다. 상단 '전환 효과 끄기'와 OS prefers-reduced-motion을 지원한다. CSP는 default-src 'none'을 유지하고 srcdoc 표시용 frame-src 'self' about:만 허용한다. iframe sandbox는 allow-same-origin만 허용하며 scripts/forms는 허용하지 않는다. :has() 미지원 구형 브라우저는 최신 프레임 정적 보기로 폴백한다.

## 확장 경계와 검증

Calendar는 구현하지 않았다. 향후 Calendar가 날짜·환경을 넘기면 `report(path, day, environment)`와 `build(legacy, attempts)`를 통해 해당 날짜의 프레임을 생성할 수 있다. qry_tp=4는 별도 결산 화면의 영역이며 이번 타임라인에 섞지 않는다. API·수집 일정·스키마 변경은 필요하지 않다.

```powershell
python -B -m unittest discover -s tests -p test_bubble_timeline.py -v
python -B -m unittest discover -s tests -v
git diff --check
```

정렬·동시각 prefix·기본 최신·날짜/환경/유형/운영 분리·누락·최초 관측·지속성·신규/이탈·다중 소속·안정적 중심·면적 비율·시세 배치 분리·읽기 전용·CSP/escaping·실제 CLI 및 브라우저 선택/터치/키보드/표 전환/효과 끄기를 검증한다. 생성물과 브라우저 캡처는 로컬 data에 보관한다.

하루 10회 수준을 대상으로 전체 HTML을 미리 포함하므로 단일 회차 파일보다 크다. 회차가 크게 늘어나는 사용이나 다른 브라우저·스크린리더·프레임 스크롤 사용성은 추가 검증 대상이다. 운영 수집 방식은 그대로 두며 이번 단계에서 커밋·푸시하지 않는다.
