# Step 7-A: D0·D+1·D+2 독립 추적 엔진

`kiwoom_collector.leader_tracking`은 저장된 Step 6-D 적격성 보고서를 입력받는 오프라인 분석 계층이다. 수집기, DB, 인증, UI, 스케줄러 또는 주문 모듈을 호출하지 않는다. 모든 예시는 합성 자료이며 매수 신호나 검증된 수익 전략이 아니다.

## 데이터 모델과 사용 순서

1. 기존 `eligibility_dashboard.build(...)['eligibility']` 보고서를 준비한다. 기존 0198·0186·ka10001 결합 및 검증 결과를 그대로 재사용한다. 이 단계에서 새 API 호출은 없다.
2. `snapshot_from_review(report, stock_code=..., captured_at=..., created_at=..., market='KRX', stock_name=..., primary_sector=..., d0_bar=...)`로 D0를 동결한다. 종목명·대표 섹터는 선택 당시 확인한 경우에만 명시적으로 전달한다. 복수 섹터는 기존 행의 `sectors`를 보존한다.
3. D+1·D+2 및 과거 일봉을 별도의 `Observation`으로 생성한다. 원문은 `raw_json`, 출처는 `source`에 전달한다.
4. `analyze(snapshot, events, calendar=calendar, as_of=aware_timestamp)`를 호출한다. 결과는 원본 이벤트와 별개의 파생 사영이다. Decimal 결과의 JSON 직렬화에는 `canonical(result)`를 사용한다.
5. 저장이 필요하면 `MemoryRepository`에 스냅샷과 이벤트를 추가한다. 이 저장소는 프로세스 내 테스트 전용이며 재시작하면 사라진다. 영속 운영 저장소는 이번 단계에 구현하지 않았다.

### D0 Snapshot

불변 frozen dataclass에 코드, mock/real 환경, 시장, D0 거래일, 포착 시각, 생성 시각, 데이터 버전, 직렬화된 선택 당시 payload와 선택 당시 확인된 D0 일봉을 보존한다. 모든 시간은 timezone-aware 입력을 요구하고 KST로 정규화한다.

payload는 종목명, 대표 섹터, 복수 섹터 태그, 0198 순위, TOP5 반복 횟수, 0186 순위, 거래대금 원본·환산값, 검증된 시가총액·시총 구간, 당일 등락률, 검증 상태·보류 사유, candidate_confirmed, 원본 보고서 행 및 원본 sources를 보존한다. 환산 거래대금은 기존 진단값이며 별도의 검증 승격을 하지 않는다. 원본 시총값과 진단값도 original_row 안에 남는다. 누락값은 null이고, `is_execution_record=false`이다. 기존 `candidate_confirmed=false`를 변경하지 않는다.

payload 조회는 매번 새 dict를 반환하므로 외부의 중첩 값 수정도 내부 기록에 영향을 주지 않는다. 원본 입력 수정도 동결 이후 영향을 주지 않는다. D0 일봉은 `post_market`·`received`이며 선택 시점 이전에 실제 확인된 경우에만 스냅샷에 포함할 수 있다. 장중 포착 후 확인한 D0 종가는 별도 이벤트로만 추가하며 D0 스냅샷은 보완·수정하지 않는다.

### Observation

코드, 환경, 시장, 거래일, 시장 기준 시각 `market_at`, 실제 확인 가능 시각 `available_at`, 장 구분 `phase`, 출처, 수신 상태, OHLCV, 일일 거래대금(원), 선택적 VWAP 분자·분모, 원문 JSON, 버전을 가진다. 부분 자료는 개별 null로 유지한다. 음수·비유한 수치, 모순된 OHLC, timezone 없는 시각, 시장 시각보다 빠른 확인 시각을 거부한다.

일봉의 장 구분은 제공자가 검증해서 전달해야 한다. 시각만으로 장 마감을 추정하지 않는다. `pre_market`, `intraday`, `post_market`을 구분하며, 장전·장중 값은 최종 일봉이나 이동평균으로 승격하지 않는다. 휴장과 거래정지 역시 구분한다.

## 거래일 캘린더

`TradingCalendar.offset(origin, sessions)` 프로토콜은 정확한 거래일 또는 None을 반환한다. `FixtureCalendar`는 명시적인 open_dates, closed_dates, 출처를 받는다. 주말조차 closed_dates에 선언해야 한다. 경로 중 하루라도 미확인이면 이후 거래일을 건너뛰어 추정하지 않고 None을 반환한다. D0가 거래일인지 확인되지 않아도 보류한다. 역방향 offset도 같은 규칙으로 전일·이동평균 구간에 사용한다.

`tests/fixtures/leader_tracking_synthetic.json`의 2026-10-27 휴장은 **합성 테스트 설정**이며 실제 거래소 휴장일 선언이 아니다. 금요일 D0→월요일 D+1, 합성 휴장일 후 수요일 D+2를 검증한다.

## 관측 상태와 종료

| 상태 | 의미 |
| --- | --- |
| calendar_unknown | 거래일 경로가 확인되지 않음 |
| pending | 확인된 추적 거래일이 as_of보다 이후 |
| not_received | 해당 시점까지 자료가 없거나 명시적 미수신 이벤트 |
| halted | 명시적 거래정지 관측 |
| received | 자료 수신; 개별 필드 누락 가능 |

에피소드 `completed`는 D+1·D+2 양쪽 모두 post_market·received이며 OHLCV 필드가 있는 경우에만 성립한다. 나머지는 `tracking`이다. 거래정지나 미수신은 시간이 지났다는 이유로 완료 처리하지 않는다. 지표·과거 데이터 부족은 추적 완료와 별개다. 부분 OHLCV는 데이터가 도착했더라도 완료 처리하지 않는다. 강제 종료·영업일 경과 만료·매수 여부 판정은 없다.

## 지표와 복수 관찰 패턴

전일 대비 등락률은 정확한 직전 거래일의 확인된 종가를, D0 대비 가격·거래량 변화는 확인된 D0 일봉을 기준으로 한다. D0 고가 돌파는 추적 고가가 D0 고가보다 클 때, 저가 이탈은 추적 저가가 D0 저가보다 작을 때다. 같으면 돌파·이탈이 아니다. 필요한 입력이 없으면 None이다.

3·5일선은 현재 확인된 마감 종가와 정확히 연속된 이전 거래일의 마감 종가로 계산한다. 충분한 구간·종가·확인 시각이 없으면 None이다. 장중 이동평균 대용치는 계산하지 않는다. VWAP는 명시적인 실제 가격×거래량 합계 / 해당 합계의 거래량으로만 계산한다. OHLC 평균이나 현재가·종가·일일 거래대금으로 역산하지 않는다. 분자·분모의 같은 시장·기간·단위 검증은 Step 7-B 입력 어댑터 책임이다.

| 패턴 ID | 분류 기준 |
| --- | --- |
| uptrend_continuation | 전일 및 D0 종가 대비 상승; 관찰 분류일 뿐 추세의 확증 아님 |
| d0_high_breakout | D0 고가 초과 |
| d0_low_breakdown | D0 저가 미만 |
| correction_with_lower_volume | D0 종가 대비 조정 범위와 거래량 감소 기준을 함께 충족 |
| correction_near_short_ma | 위 조정 범위이며 확인된 3일선 또는 5일선에 근접 |
| insufficient_data | OHLCV, D0 종가 비교 또는 이동평균 판단 자료 부족 |

각 패턴은 동시에 성립할 수 있으며 부족 상태도 다른 관찰과 공존한다. 충분한 자료로 어느 패턴도 성립하지 않으면 빈 tuple이다. 기본 조정 범위 0.5~10%, 거래량 감소 20% 이상, 이동평균 근접 ±2%는 `PatternConfig`로 변경 가능하다. 이는 테스트 가능한 임시 관찰 기준이며 건강한 눌림, 수익성, 매수 적격성을 확정하지 않는다. 거래량 감소만으로 조정 패턴을 만들지 않는다.

## 미래 누출·출처·중복 통제

- D0 어댑터는 미래 수집·요청·응답·시총 시점을 거부한다. 원본 환경 혼합과 시총 코드 불일치도 거부한다.
- 모든 이벤트는 동일 코드·환경·시장이어야 한다. 미래 이벤트도 다른 환경을 섞어 전달하면 거부한다.
- 시장 시각과 실제 확인 시각 모두 as_of 이하여야 결과에 노출한다. 과거 날짜로 지연 수신된 자료도 확인 시점 이전에는 보이지 않는다.
- 특정 일자의 관찰 지표에는 그 관찰 이벤트 당시까지 확인된 과거 일봉만 사용한다. D+2에 도착한 과거 가격으로 D+1 지표를 소급 개선하지 않는다.
- 같은 날짜에 여러 이벤트가 있으면 확인 시각이 가장 늦은 가시 이벤트를 사용한다. 같은 확인 시각에 다른 값이 존재하면 임의 선택하지 않고 오류를 낸다.
- 파생 결과는 사용한 이벤트의 fingerprint·출처·시장 및 확인 시각·환경·버전, 계산 버전·설정을 보존한다. 원문은 해당 fingerprint의 원본 이벤트에 남는다.
- 에피소드 키는 코드+D0+환경+시장이다. 같은 키의 재생성은 payload가 달라도 거부한다. 다른 D0의 동일 종목은 별도 에피소드다. 동일 원본 이벤트 중복 추가도 거부한다.

## Step 7-B 실데이터 연결 계획

1. 읽기 전용으로 이미 보존된 0198·0186·ka10001·Step 6-D 자료의 종목명, 섹터 태그, 시장, 실제 확인 시각을 바인딩한다. snapshot 생성 시 현재 값을 과거 값처럼 대입하지 않는다. 후보 확인 상태를 자동 변경하지 않는다.
2. 공식 거래소 거래일·휴장일 근거와 적용 시장을 갖춘 캘린더 공급자를 구현한다. 임시·특별 휴장, 시장별 거래일 차이, 커버리지와 버전도 관리한다. 확인 전에는 fixture 결과를 실운영 거래일로 사용하지 않는다.
3. 승인된 저장 자료 또는 향후 별도 승인된 일봉 데이터/API에서 OHLCV·원화 거래대금·직전 종가와 최소 4거래일 이전 종가를 확보한다. 현 단계에서는 API/OAuth를 호출하지 않는다. 실제 사용할 API ID는 공식 명세·응답 단위 검증 후 결정한다.
4. 장전·장중·마감 확정, 거래정지와 미수신, 시장별 합산 범위, 누적/최종 거래량, 수정주가·액면분할·권리락 정책을 명시한다. 가격 기준이 서로 다른 일봉을 섞지 않는다. 필요하다면 비교 보류 사유를 확장한다.
5. VWAP는 동일 시간 구간의 체결 가격·거래량 원본 또는 검증된 공식 누적 분자·분모가 확보된 경우에만 연결한다. 단순 현재가와 종가 입력으로 대체하지 않는다.
6. 공급자의 원본 응답 식별자와 market_at/available_at을 변조 없이 보존한다. 현재 엔진은 시각·출처 주장의 진위를 인증하지 않으므로 어댑터의 증거 검증이 필요하다. 기존 데이터에 시각 근거가 없으면 미확인으로 보존하고 과거 분석에 승격하지 않는다.
7. 영속화가 필요하면 운영 DB와 분리된 저장소에서 unique episode key, append-only 원본 이벤트, 원자적 중복 방지, 버전별 파생 결과를 구현한다. 현재 메모리 저장소는 동시성·재시작 보존을 제공하지 않는다.
8. 수신 지연·정정·중복·장중→마감 전환의 실제 저장 응답 fixture를 비식별화해 회귀 테스트한다. 인증정보·DB·로그를 Git에 추가하지 않는다. 신규 UI·주문·자동 매수·기존 정기 수집기 변경은 이 단계 범위에 포함하지 않는다.
