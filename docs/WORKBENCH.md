# 최근 미분류 종목 작업실 (Step 3-D)

기존 `sector workbench`를 개선했습니다. API·서버 없이 읽기 전용 SQLite 스냅샷으로 HTML을 생성합니다. 창에서의 선택은 CSV 초안이며 DB 태그가 아닙니다. 기존 파일은 덮어쓰지 않고, 새 출력명을 사용합니다. 이번 단계에서 실제 분류 적용·수집·스케줄 활성화는 하지 않습니다.

## 기존 구현과 보완한 부분

| 기존 기능 | 재사용 / 보완 |
|---|---|
| `sector export-priority` | 성공한 환경별 순위·조건검색의 미분류 합집합과 기존 누적 순서를 재사용. 명령과 3열 CSV는 변경하지 않음 |
| `sector workbench` | 최근 TOP20·TOP5·TOP10 회차 수, 최근 순위 관측 날짜, 최신 회차 신규 진입, 최신 TOP20 필터, 현재 미분류 상태 추가 |
| 섹터 검색·별칭·복수 태그 | 기존 구현 유지. 이름만으로 자동 배정·삭제·통합하지 않음 |
| 수동 확인·CSV 다운로드 | 기존 출처·자료 확인일·이용조건 확인 유지. 자동 확인 없음. UTF-8 BOM·8열·복수 행 형식 유지 |
| `sector import --dry-run` | 기존 읽기 전용 검증 재사용. 별칭 정규화·중복·메타데이터·공존 충돌 표시 |
| `sector import` / `import-report` | 기존 importer와 보고서 재사용. 실제 적용은 별도 검토·승인 후에만 수행 |
| 코드 지원 제한 | 기존 CSV가 지원하지 않는 원본 코드를 읽기 전용 보류 목록에 보존. 임의 숫자 변환·마스터 등록 없음 |

## 우선순위와 관측 범위

최근 기간은 **HTML 생성 시각(KST) 직전 7×24시간부터 생성 시각까지**, 양 끝을 포함합니다. `collections.status=success`, `api_id=ka00198`, 해당 환경, `test_mode=0`, 순위 1~20만 셉니다. 같은 종목의 등장 횟수는 고유 collection_id 수이며, TOP5·TOP10은 그 회차의 순위로 셉니다. 서로 다른 qry_tp도 별도 회차입니다. 날짜 수·거래량·시세 강도 점수가 아닙니다. 미래 시각·시간대 없는 시각·잘못된 시각은 최근 통계에 사용하지 않습니다.

작업실 기본 순서는 최근 TOP20 횟수 → TOP5 횟수 → TOP10 횟수 → 최근 순위 관측 시각입니다(모두 내림차순). 완전 동률은 기존 누적 우선순위로 결정합니다. 가중치 점수는 없습니다. **기존 누적 우선순위** 선택으로 이전 흐름도 사용할 수 있습니다. `export-priority`는 호환성을 위해 기존 정렬을 유지하므로 기본 작업실과 순서가 다를 수 있습니다.

대상 합집합 조회는 기존 `priority_rows()`를 사용합니다. 조건검색만 등장한 미분류도 보존하고 최근 순위 횟수는 0, 순위 관측 날짜는 없음으로 표시합니다. 과거에만 등장한 종목도 버리지 않습니다. 최근 관측 날짜는 마지막 유효 **순위** 관측 일자이며 생성 일자나 조건검색 일자가 아닙니다. 현재 태그는 환경과 별개인 공통 수동 태그 스냅샷입니다.

신규 진입은 최신 성공 운영 TOP20과 **같은 KST 날짜·환경·qry_tp·test_mode=0**의 직전 성공 회차에서 코드 집합을 비교합니다. 실제 수집 시각순이며 같은 시각이면 저장 순서입니다. 비교 회차가 없으면 신규 여부는 null/비교 없음입니다. 상장 신규·시장 최초 등장이라는 뜻이 아닙니다. 최신 관측이 과거 날짜여도 그대로 표시하고 API를 호출하지 않습니다. 최신 TOP20 필터는 이번 회차 미분류를 빠르게 검토하는 기능입니다.

현재 태그가 하나라도 있으면 기존 작업실처럼 분류 대상으로부터 제외합니다. 작업실의 `현재 DB 태그: 없음`과 이번 CSV 초안을 구분합니다. 기존 태그 추가의 근거는 `stock_sectors.source`, `stock_sector_events`, 기존 외부 importer의 `sector_tag_evidence`·출처·이용조건 이력에 남습니다. HTML에서 과거 태그를 재현하거나 출처를 자동으로 만들지 않습니다.

## 코드 호환성 보류

순위 수집과 Radar는 문자 포함 코드 등을 보존하지만, 기존 `stocks`·`stock_sectors`·CSV importer는 **6자리 숫자 코드**만 지원합니다. 이 제한은 이번 단계에서 변경하지 않습니다. 지원하지 않는 유효 순위 코드는 이름·원본 코드·최근 횟수·최신 회차 여부를 보류 목록에 표시합니다. CSV 선택 대상에 넣거나 숫자로 바꾸지 않습니다. 숫자 코드용 기존 CSV와 스키마를 보존하기 위한 제한이며 해당 종목에 섹터가 없다는 사업적 판단이 아닙니다.

## 사용 절차

```powershell
python -B -m kiwoom_collector sector workbench --environment mock --db .\data\stock1.db --output .\data\sector-workbench-recent-new.html
Start-Process .\data\sector-workbench-recent-new.html
```

1. 최근 횟수·날짜·신규 여부를 보고 종목을 선택합니다. 필요하면 최신 TOP20만 표시합니다.
2. 반도체·반도체 소부장·로봇·2차전지 등 큰 범주부터 근거를 검토합니다. 종목명만으로 확정하지 않습니다.
3. 기존 섹터 검색·별칭 선택·다중 태그·수동 출처 확인 절차를 그대로 사용합니다. 근거가 없으면 확인하지 않은 상태로 남깁니다.
4. 확인한 태그만 CSV로 다운로드합니다. CSV 초안과 실제 적용은 별개입니다. 필터 변경·선택 해제는 기존 DB 태그를 삭제하지 않습니다.
5. 다운로드한 파일의 실제 경로로 읽기 전용 검증을 실행합니다.

```powershell
python -B -m kiwoom_collector sector import .\data\reviewed-tags.csv --environment mock --db .\data\stock1.db --dry-run
```

오류가 없더라도 충돌과 근거를 사람이 검토해야 합니다. 실제 적용은 DB를 변경하므로 **별도 승인 후** 같은 명령에서 `--dry-run`을 뺍니다. 적용한 이력이 있을 때만 다음 보고서를 확인합니다. 이번 개발에서는 운영 DB에 import를 실행하지 않습니다.

```powershell
python -B -m kiwoom_collector sector import-report latest --db .\data\stock1.db
```

기존 3열 우선순위 CSV 및 8열 작업실 CSV와 importer를 변경하지 않았습니다. 3열 CSV는 기존과 같이 출처·확인일·이용조건 메타데이터를 별도로 입력해야 합니다. 실전 관측 DB는 `--environment real`로 읽을 수 있으며 서버 호출을 뜻하지 않습니다.

## 검증

가상 DB에서 최근 빈도·TOP5/TOP10·시간대·7일 경계·신규 비교·환경/테스트 분리·복수 태그 제외·미지원 코드 보류를 확인합니다. 실제 로컬 브라우저에서 검색·최신 필터·기존 정렬 전환·수동 확인·CSV 다운로드 내용·기존 dry-run 왕복을 검증합니다. 기존 전체 회귀 테스트도 유지합니다.

2026-10-23 Windows / Python 3.11.9의 격리 복사본에서 전체 **383개(기존 366개 + 신규 17개)**가 통과했습니다. 실패·오류·skipped는 0개, unittest 실행 74.958초였으며 보호 파일 98개가 동일했습니다. 기존 수집 엔진·Radar·스키마·외부 importer·스케줄은 변경하지 않았습니다. 실제 DB/WAL/SHM은 WAL이 빈 상태를 확인한 뒤 source mode=ro&immutable=1의 SQLite backup API로 복사하고, 원본의 해시·크기·수정 시각 보존을 확인했습니다. WAL이 비어 있지 않거나 원본이 변하면 이 immutable 백업 방식을 사용하지 않고 중단해야 합니다.

실제 mock 자료의 최근 미분류는 CSV 검토 가능 40종목과 코드 보류 3종목입니다. 최신 저장 회차는 2026-10-20 15:00, 비교 회차는 같은 날짜 14:00입니다. Radar v2의 미분류 12종목 중 숫자 코드 10종목은 기존 검토·CSV 경로를 사용할 수 있으며 `0035S0`·`0158S0`은 코드 호환성 보류입니다. 전체 보류 목록에는 과거 회차의 `0161M0`도 포함됩니다. 실제 분류·import 적용은 0건이며 10종목의 사업 근거를 확인했다는 뜻이 아닙니다. 최근 창은 생성 시각에 따라 이동하므로 이 수치는 해당 스냅샷 검증 결과입니다.
