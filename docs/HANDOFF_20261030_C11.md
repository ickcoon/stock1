## Git 및 집 PC에서 재개

인계 대상은 코드·테스트·검토 문서뿐이다. 운영 .env, 실전 키, 토큰, DB,
스냅샷, diagnostics, reports, 로그, 잠금·임시 파일은 포함하지 않는다.
추적된 .env.example에는 빈 키 항목만 있다.

기존 미커밋 로컬 문서 4개는 원래 상태로 보존한다:
COLLECTOR_RECOVERY_20261030.md, COLLECTOR_UNATTENDED_PLAN_20261030.md,
STEP7_C9A_SQLITE_ACCESS_ANALYSIS_20261030.md, STEP7_C9_HOSPITAL_RESULT_20261030.md.
이 문서들과 로컬 manifest·테스트 로그·DB는 Git pull로 집 PC에 전달되지 않는다.
필요한 안전한 오류 메타데이터는 위 표로 인계한다.

집 PC에서는 먼저 작업 폴더·브랜치·미커밋 변경을 확인하고 아래 순서로 진행한다.

```powershell
git status --short
git branch --show-current
git fetch origin
git log --oneline --left-right HEAD...origin/main
# 로컬 main에 충돌·분기·보존할 미커밋 변경이 없는 경우에만:
git pull --ff-only origin main
```

로컬 변경이 있으면 별도 보존·검토 후 진행한다. 분기·충돌 시 중단하고
reset/clean/강제 push로 덮어쓰지 않는다. 다른 브랜치를 확인 없이 main으로 전환하지 않는다.
집 PC의 인증정보·DB는 자동 생성·복사하지 않는다. `catalog_real --help`와 합성 회귀 테스트로
개발을 시작하고 실제 수집 승인 플래그는 사용하지 않는다. 운영 .env 경로가 없으면 실수집
CLI가 중단하는 것이 정상이며 보호 조건을 제거하지 않는다.

이번 종료 시 새 기능 구현·오류 로직 변경·실제 API 재호출은 하지 않았다.
최종 Commit SHA와 원격 일치 여부는 완료 보고 및 Git 로그에서 확인한다.
