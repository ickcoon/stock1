# C15-10 오전 섹터 흐름 및 0186 단위 검증

2026-11-05 실제 저장 자료로 검증했다. 기존 점수 가중치와 C15-7/8/9 선정을 유지하고 시간축 비교만 추가했다. 운영 Collector·스케줄·키·DB 수정, 실전 API 호출, Telegram 발송, commit/push, 운영 배포는 하지 않았다. 공개 공식 명세만 웹에서 확인했으며 분석·테스트는 SQLite 읽기 전용이다.

## A. 실제 구현

- `kiwoom_collector/c15_flow.py`: 작은 별도 CLI. 기존 `c15_preview.generate`로 세 슬롯을 재현하고, TOP3 밖을 포함한 전체 43개 관측 테마의 점수·순위·상승 수·관측 수·대표 종목·출처·매핑 상태를 비교한다.

- `kiwoom_collector/c15_turnover_audit.py`: 저장 응답 페이지/행/선택 스냅샷 대조, 별도 명세 환산. 원본과 기존 점수 입력을 변경하지 않는다.

- 신규 테스트: `test_c15_flow.py`, `test_c15_flow_actual.py`, `test_c15_turnover_audit.py`. 이 보고서 외 기존 C15 파일은 위 관심 계산 추출 이외에 수정하지 않았다.

### 세 시점 공통 0198 관심 비교점수

### 원본 저장값 대조

09:40 100행, 09:50 100행에서 SQLite `turnover_pages.response_json`의 응답 행, `turnover_rows.raw_json`, C15가 선택한 스냅샷 행의 전체 내용과 코드·거래대금 값이 일치했다. 별도 `normalized_json`의 백만원 선언 및 진단용 원화 환산도 일치했다. 09:45는 자료가 없다.

**한계:** 기존 `response_json`은 Collector가 필드를 제한해 저장한 응답 부분집합이다. 독립적인 HTTP wire 원문 파일이 아니므로 “네트워크 원문 바이트 대조 완료”라고 주장하지 않는다. 원시 저장값은 변경하지 않고 계산 결과를 개발 JSON에 별도 보존한다.

### 억원 환산 예시 3개 — 실제 09:40 원시 저장값

| 종목 | 응답/행 원본 `trde_prica` | 공식 명세 환산 원 | 공식 명세 환산 억원 |
|---|---:|---:|---:|
| SK하이닉스 | `788193` | 788,193,000,000 | 7,881.93 |
| 삼성전자 | `767341` | 767,341,000,000 | 7,673.41 |
| KODEX 200 | `355352` | 355,352,000,000 | 3,553.52 |

산식은 `원 = 원본 × 1,000,000`, `억원 = 원본 ÷ 100`이다. 사용자 HTS 예시 `306,023`도 백만원이라는 전제에서 306,023,000,000원 = 3,060.23억원이며 산술 테스트를 추가했다. 이 예시는 같은 시각·종목·거래소의 REST 실측 검증값으로 사용하지 않았다.

### 점수 반영과 전후 순위

**공식 REST 계약 단위는 백만원으로 확인**, 저장 경로도 일치하지만 **동일 시각 독립 대조와 누적 거래대금 기준은 여전히 미검증**이다. 기존 `unit_runtime_verified=false`, 누적 기준 보류, 기존 스냅샷별 단위 증거 게이트를 유지한다. 단위를 확인했다는 이유만으로 시총·유동성·시장시각까지 통과시키지 않는다.

따라서 `documented_won`, `documented_eok`는 별도 명세 환산 표시이며 `scoring_allowed=false`다. 브리핑에도 “명세환산·실측미검증”을 붙인다. **금액 점수는 OFF→OFF**이고 환산 표시 전후 기존 섹터 순위는 동일하다. 검증 후 활성화한 순위는 아직 계산하지 않았으며 JSON의 `enabled_ranking`은 NULL이다. 임의 금액 가중치나 가짜 활성화 실험을 추가하지 않았다.

## G. 일별 추적 기반과 C15-11 권고

기존 운영 SQLite에는 C15 점수 이력 표가 없다. 기존 C15-9의 시각별 `preview.json`과 `tracking_observations`를 그대로 재사용하고 이번 `flow.json`에 전체 슬롯·원점수·상태 근거·판정 컷오프·비교 코드를 추가했다. 원본 스냅샷 해시와 공식 마스터 근거는 함께 저장한 시각별 `preview.json`에서 확인할 수 있다. 이 구조를 날짜·슬롯·정책/매핑 버전·테마 기준으로 연결하면 D+1/D+2 및 캘린더의 관측 근거로 쓸 수 있다. 운영 DB에 새 표를 만들거나 장기 추적 엔진을 추가하지 않았다.

C15-11은 다음 순서가 적절하다.

1. 동일 시각·종목·거래소·조회 조건의 HTS/독립 근거와 저장 REST를 대조해 실측 단위·누적 기준을 검증한다. API 호출 없이도 제공받은 저장 자료로 가능하다.
2. 09:45 누락과 첫 페이지 경계 편향을 개선할 수집 설계를 검토한다. 운영 변경은 별도 승인·작업으로 분리한다.
3. 테마/상품 코드 연결과 수신 시각을 보완하고, 기존 이름 변형은 검토된 별칭으로만 정리한다.
4. 여러 날짜의 같은 시각끼리 같은 정책·동일 관측 패널로 비교한다. 미관측·미분류를 약세로 채우지 않고 과거 시점의 소속·시세를 나중 지식으로 바꾸지 않는다.
5. 상태 기준의 창 길이·변화 허용폭을 여러 날로 평가한다. 현재 두 시점의 잠정 지속·약화를 장기 교체 정답으로 쓰지 않는다. ADR20과 외부 테마 요약은 계속 보조 참고이며 점수·정답에 투입하지 않는다.
