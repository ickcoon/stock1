# STOCK1 시장 테마 분류 정책

기준일: 2026-10-24. 메인 섹터는 기업의 일반 산업분류보다 국내 주식시장에서 널리 통용되는 큰 시장 분류를 우선한다. 실제 사업·공시·테마 연결 근거를 확인한 뒤 채택한다. 본업과 시장 테마를 검토표의 별도 항목으로 기록하며, 외부 확인 완료와 미확인 후보를 구분한다.

기존 정식 섹터명을 먼저 조회하고 의미가 같은 신규 명칭 생성을 피한다. 복수 테마는 각각 근거를 기록한다. 기존 태그와 과거 기록은 임의 삭제·개명·통합하지 않는다.

## 제약·바이오

제약·바이오는 정책상 넓은 하나의 메인 섹터로 관리하며 신규 검토의 명칭은 `제약·바이오`를 우선한다. 전통 제약사·신약개발·바이오 플랫폼은 시장 전체의 수급 순환과 동반 상승 관찰을 위해 함께 검토하고 불필요하게 세분화하지 않는다.

기존 `바이오` 종목 연결과 근거·과거 기록은 그대로 유지한다. `바이오`를 `제약·바이오`로 자동 변경하거나 별칭으로 강제 연결하지 않는다. 신규 명칭 채택은 별도 승인된 적용 작업에서만 수행한다. 따라서 두 명칭은 당분간 DB와 Radar에서 별도 그룹으로 공존할 수 있다. 현행 Radar는 현재 태그 기준이므로 두 그룹을 합쳐 보여주지 않으며, 향후 정책상 합산 지표가 필요하면 코드 중복을 제거하는 별도 설계가 필요하다.

## 독립 테마와 일회성 사건

비만·GLP-1, 탈모, 양자보안, 광통신, 스페이스X 등 독립적인 시장 테마는 필요할 때 실제 사업·공시·테마 연결 근거를 확인하여 별도 태그로 관리한다. 예시 명칭 자체는 신규 태그 생성이나 종목 편입의 근거가 아니다. 기존 정식 명칭과 의미 중복을 먼저 확인하고 하나의 종목에 메인 섹터와 복수 테마를 함께 부여할 수 있다.

FDA 승인 등 종목별 일회성 사건은 장기 섹터 태그와 구별한다. 향후 날짜별 이벤트 기록 대상으로 검토하되 이번 정책은 이벤트 테이블·수집 기능을 추가하지 않는다.

## 관측 이력 보존

코스닥 섹터 순환과 대장주 상승 이후 다른 종목의 관심도·거래대금 변화를 추적할 수 있도록 순위·시세·수집 시각·원본 이력을 보존한다. 조회순위 표본을 시장 전체 수급으로 해석하지 않으며, 거래대금은 검증된 단위·시점·누락 범위 안에서만 비교한다. 현재 태그를 과거 관측에 적용한 분석과 당시 분류 이력을 구별한다.

## 기존 5종목 후보와 호환성

- `014950 / 삼익제약`은 로컬 저장값이다. 우선 검토 후보는 `제약·바이오`이며 공식 코드·법인명 식별과 사업 근거 확인 전에는 적용하지 않는다. 기존 후보의 `바이오 검토 보류` 제안은 이 정책으로 대체한다.
- 기존 5종목 CSV는 역사적 초안으로 보존하며 정책 변경을 이유로 덮어쓰거나 가져오지 않는다.
- `제약·바이오`는 기존 `바이오`와 별도 명칭이며 이번 정책 문서화만으로 DB에 생성하지 않는다.
- 기존 다대다 `stock_sectors` 및 근거 importer로 복수 테마를 표현할 수 있어 정책 자체를 위한 스키마·수집 엔진·스케줄 변경은 필요 없다.
- 별도 승인된 2종목 적용 범위는 코리아써키트의 기존 `반도체 소부장`, 라온시큐어의 `양자보안`뿐이다. 제약·바이오 정책이 다른 종목의 적용 승인으로 확대되지 않는다.

## 관련 문서와 역할 구분

이 문서는 분류 명칭과 채택 기준을 정의한다. 아래 문서의 사용 절차·저장 명세는 반복하지 않고 그대로 따른다. 관련 문서와 큰 범주 우선·근거 확인·복수 태그·기록 보존 원칙을 대조했으며 모순은 없다.

- [섹터 작업실](WORKBENCH.md): 큰 범주부터 검토하고 확인된 태그만 CSV로 내보내는 절차, 기존 8열 CSV와 별칭·복수 행 형식을 유지한다. 문서의 섹터 예시는 허용 목록을 제한하지 않는다.
- [Radar v2](SECTOR_RADAR.md): 기존 명칭·현재 태그를 그대로 사용하며 복수 섹터 집계와 미분류 표시를 유지한다. 정책 변경만으로 기존 그룹을 합산하거나 화면·계산식을 바꾸지 않는다.
- [DB 명세](DATABASE.md): 기존 태그·출처·근거·감사 이력을 보존한다. CSV 누락을 태그 철회로 해석하지 않는다. 이번 정책 정리에는 DB·스키마·수집 엔진·정기 스케줄 변경이 없다.

`제약·바이오`를 넓은 하나의 섹터로 관리하는 정책과 기존 `바이오`를 보존하는 호환성 원칙을 함께 적용한다. 이는 기존 태그를 자동 병합한다는 뜻이 아니며 현행 Radar의 별도 그룹 표시는 유지된다.
