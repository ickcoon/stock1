# C15-12 운영 연결 준비

개발 코드에만 구현했다. 운영 파일·DB·스케줄·키 변경, 실전 API 호출, 실제 Telegram 발송, commit/push는 하지 않았다. 전종목 상품 마스터나 신규 수집 시스템은 만들지 않았다.

## A. 연결 코드와 사용법

- `c15_delivery.py` 신규: C15 결과를 기존 Telegram 계약에 연결하는 어댑터. 시점별 결과를 먼저 동결 저장하고 재실행은 그대로 재사용한다. 로컬 상세 진단과 경로를 제거한 전달 보고서를 분리한다.
- `operating_workflow.py`: `morning_review` 진입점에 기본 비활성 `c15_briefing_enabled` 분기만 추가했다. 기존 경로는 그대로다.
- `telegram_briefing.py`: C15 스키마 검증/본문 생성 분기와 시점별 예약 키를 추가했다. 수신자 allowlist, readonly opt-in, 개인정보 검사, 본문 일치 검증, 독점 예약, 실패 시 재시도 차단은 기존 코드다. 새 Telegram 클라이언트 없음.
- `c15_briefing.py`, `c15_briefing_data.py`: opt-in 실용 상품 필터와 최근 시총 범위 표시를 추가했다. C15-11 기본 미리보기는 유지한다. 기존 점수와 가중치는 바꾸지 않았다.
- `tests/test_c15_delivery.py`: 실제 저장 자료 Workflow 재생 및 모의 전송 경계 검증.

향후 설정은 `c15_briefing_enabled=true`, `c15_preview_config=<배포 대상에 맞춘 설정 경로>`다. `telegram_send_enabled`는 기존 설정으로 별도 관리한다. 이번 재생은 false이며 자격증명도 읽지 않았다. 새 CLI나 send 명령을 추가하지 않았다. Python에서 기존 `Workflow.morning_review(store, due, turnover_path)`를 호출하면 위 opt-in 분기를 통과한다.

## C. 상품 제외

공식/검증된 분류가 우선이다. 유형이 불명확한 경우 KODEX/TIGER 등 명확한 브랜드 접두어, 독립 ETF/ETN 표기, 리츠/스팩 접미어를 보수적 후보 제외에 사용한다. 이름에 의한 제외는 `conservative_name_excluded`이며 공식 유형 확정으로 기록하지 않는다. 이름·일치 문자열·패턴·정책 버전을 종목별 진단에 남긴다.

## D. 통합 검증

관련 고유 테스트 **307개 통과**: 기존 C15 회귀 220개와 최종 Telegram/아침 Workflow·신규 어댑터 87개다. `test-results.json`에 실행 범위를 기록했다. 실제 저장 자료로 세 시점의 `Workflow.morning_review → C15 어댑터 → telegram_briefing.validate/summary → deliver`를 확인했다. 기본 비활성, 동결 재생, 메시지 변조 거부, 수신자 제한, readonly opt-in, 기존 발송 예약에 의한 차단, 시점별 중복 차단, preflight 예약 일치를 검증한다. 전달 보고서는 기존 JSON 크기 제한 안으로 줄였고 전체 근거는 별도 진단에 보존한다.

전송 모의 실행은 합성 자격증명을 사용하고 `api_call`을 HTTP 진입 전에 강제로 중단했다. 따라서 결과는 의도적으로 `failed_or_unknown`, `message_sent=false`이며 두 번째 호출은 `duplicate_blocked`다. 실제 Telegram 성공 발송을 검증한 것은 아니다. `integration-validation.json`에 기록했다. 테스트 상태는 개발 `mock/notification_state`에만 저장되어 운영 중복 방지 상태와 분리된다.

## E. 운영 반영 최소 목록

실제 운영은 개발 버전과 달리 `Workflow.review` 안에서 아침 처리를 하며 별도 `morning_review`가 없다. 따라서 개발 Workflow 전체 복사로 반영하면 안 된다.

1. 새 어댑터와 필요한 C15 모듈/설정 및 Telegram 계약 분기를 검토한 파일 단위로 반영한다.
2. 운영 `Workflow.review`의 기존 아침 분기 입구에서 opt-in 어댑터 호출을 연결한다. 기존 오후 경로와 수집 동작은 유지한다.
3. preview 설정의 runtime, 일별 DB, 테마 DB 등 경로를 배포 대상과 맞춘다. 진단 PC 경로를 그대로 배포하지 않는다. 결과 저장 루트는 배포 대상 reports, 중복 방지는 기존 운영 notification_state여야 한다.
4. 오전 09:40/09:45/09:50 슬롯은 운영에 이미 있으므로 중복 추가하지 않는다. 09:45 0186 수집은 운영에 없으며 기존 미적용 패치는 별도 승인 전까지 그대로 둔다. 그동안 10분 이내 대체 정책을 사용한다.

현재 전달 키는 기존 오전 namespace 아래 `c15-slot/HH:MM`을 추가한다. 기존 오전 예약이 하나라도 있으면 세 C15 슬롯 모두 막는다. **기존 아침 발송과 C15를 동시에 가동하지 않아야 한다.** 운영 전환은 거래일 시작 전 수행하고 기존 예약을 삭제해 재전송하지 않는다. 기존 경로로 되돌리는 경우에도 당일 C15 발송 이력을 먼저 확인해야 한다.

## F. 실제 발송 전 확인

- 운영 배포와 실제 발송에 대한 별도 승인.
- 운영 버전에 맞춘 최소 어댑터 패치 및 실제 경로 검토, 기존 분기와 동시 발송 방지.
- 기존 수신자 allowlist/보호된 자격증명, notification_state 공유 경로 및 쓰기 권한 확인.
- 실환경 설정으로 발송 비활성 재생 후 세 시점 메시지와 preflight 확인. 테스트의 실패 예약을 운영으로 복사하지 않는다.
- 세 번의 잠정 브리핑 발송 정책 확인. 기존 최종/중요 변경 기반 발송 정책을 opt-in C15 경로에서 세 시점 브리핑으로 바꾸는 것이므로 명시적 전환이 필요하다.
- 09:45 대체/부분 수집, 시총 기준일, ADR 사후참고, 잠정 후보 표시 확인.

상품 전종목 마스터 구축이나 정밀 데이터 수집은 이번 단계 범위가 아니다. 잔여 미확인 자료는 추정하지 않고 진단/보류로 유지한다.
