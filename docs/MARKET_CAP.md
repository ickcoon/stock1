flo_stk를 임의로 천주/주로 해석하지 않는다. listed_shares 및 가격×주식 수 기반 시총은 null로 유지한다. mac이 전체/유통/종류주식별 어느 기준인지, 가격·주식 수 기준 시각이 같은지 등 계산 방식도 독립 확인 전 미검증이다. 수치가 비슷하다는 이유만으로 계산 방식을 확정하지 않는다.

개별 포털 URL은 이번 웹 도구에서 접근에 실패해 공식 GitHub 계약을 근거로 삼았다. 모의 NXT/SOR 실행 성공은 확인하지 않았으므로 이번 모의 계획에서는 KRX 코드만 허용한다. 실전의 _NX/_AL 형식은 원문 그대로 유지하며 실제 제공 여부는 미검증이다. 영문 포함 6자리도 문자열 형식으로 처리하지만 패턴 통과는 개별 상장/유형 검증을 뜻하지 않는다.

## 유량·오류·공식 예제 사용 주의

[공식 서비스 안내](https://openapi2.kiwoom.com/intro?dummyVal=0)에서 국내 조회는 계좌/토큰별 초당 5회, 모의 동일 TR은 초당 1회로 확인했다. 독립 계획은 요청 시작 간 1.2초를 제안하지만 기존 프로세스의 합산 유량까지 제어하지는 못한다.

[공식 오류 분류](https://raw.githubusercontent.com/Kiwoom-Securities/Kiwoom-REST-API/main/kiwoom/core/errors.py)는 HTTP 실패와 API 반환코드를 구분하고 유량(1700/1701/1702), 토큰·자격증명, 환경, 종목, 모의 미지원(8104) 등을 다룬다. 본 모듈은 HTTP 상태와 숫자 return_code를 보존하고 nonzero/missing 코드를 실패로 처리한다. 원문 return_msg나 토큰은 저장하지 않는다. 메시지에 내포된 상세 코드의 완전한 해석은 이번 범위에서 구현하지 않았다.

공식 예제는 공통 클라이언트의 자동 인증/복구와 최대 10페이지를 사용할 수 있으므로 그대로 실행하지 않았다. 독립 모듈은 종목별 단 한 번, 최대 10개, 추가 페이지·재시도·인증 복구 없음 조건이다. 실패하면 배치를 중단한다.

## 독립 모듈

`kiwoom_collector.market_cap`은 DB/인증정보를 열지 않는 표준 라이브러리 모듈이다.

- request_plan: 정확한 문자열 코드·환경으로 무통신 계획 작성. 중복 제거와 최대 10개 제한.
- plan_from_cross: Step 5-E 결과에서 실제 필터 통과·40위 이내의 소수 관찰 종목만 선택. 명시된 ETF/ETN/종류주식 등은 제외. 유형 미확인은 조회 대상으로 계획할 수 있지만 적격성 통과 불가.
- parse_response/parse_fixture: 원문 허용 필드와 Decimal 환산값 분리, HTTP/API 상태·결측·이상값·음수·코드 불일치·관측 구간·중복 검증.
- IndependentClient: 주입된 외부 transport만 사용. 기본 HTTP/OAuth 구현은 없으며 명시 승인 전 transport도 호출하지 않는다. 최대 횟수/중복 재조회/오류 이후 추가 조회를 차단한다. 실제 TLS·인증·유량 제어는 다음 승인 단계의 별도 실행 계층 책임이다.
- eligibility: 외부 증거를 특정 응답 fingerprint와 환경에 결합해 시총·장 마감 금액·순위의 3상태 검증. 후보 확정은 항상 false.

구조화한 원문은 stk_cd/stk_nm/mac/flo_stk/cur_prc만 보존한다. 응답 전체를 로그로 내보내지 않는다. 요청/수신 시각과 retrieval_date는 시장 기준 시각·거래일과 다르다. 둘을 자동 대입하지 않는다.

## 적격성 계약

일반 주식임을 별도 근거로 확인해야 한다. ETF/ETN/SPAC/우선주/REIT 등은 대상 제외, 유형 미확인은 보류다. 코드나 이름만으로 유형을 추측하지 않는다.

필수 조건은 시총 3,000억원(300,000,000,000원) 이상, 검증된 장 마감 누적 거래대금 1,000억원(100,000,000,000원) 이상, 거래대금 순위 40위 이내다. TOP5는 필수 자격이 아니라 우선 검토 조건이며 보조 관찰 종목도 유지한다. 섹터 동반 상승은 별도 검증 플래그가 있을 때만 표시한다.

단위 실측·시총 기준/계산 방식, 정확한 코드/환경, 시장 기준 시각/거래일, 장 마감 누적 기준과 시장 조건의 외부 근거가 필요하다. 증거가 바인딩되지 않거나 오래된 날짜/다른 시각이면 true로 판정하지 않는다. 이번 단계에서 임의 시차 허용값을 추가하지 않았다. 과거 Step 5-E의 300초 관측 허용은 시총 적격성의 시장 시각 검증을 대신하지 않는다.

장중 금액 미달/미검증은 장 마감 부적격 판정이나 섹터 탐지 제외를 뜻하지 않는다. 검증된 숫자 경계값 통과도 매매·주문·자동 후보 확정은 아니다. eligibility가 요구하는 외부 증거는 신뢰된 검토 절차가 공급해야 하며 단순 문자열의 진위를 인증하는 기능은 없다.

```powershell

python -B -m kiwoom_collector.market_cap fixture --input tests/fixtures/market_cap_synthetic.json
```

두 명령 모두 실제 통신 0회다. 라이브 실행 CLI는 없다. fixture의 값·유형·검증 true 사례는 합성 자료이며 실측 검증을 완료하지 않았다. 기존 시총 미확인 Bubble 패널은 이번에 변경하거나 연결하지 않았다.

## 향후 캐시 제안 — 아직 영구 캐시 구현 없음

캐시 키는 환경, 원문 전체 코드(거래소 접미사 포함), 요청된 거래일, 계약 버전, 단위/계산근거 버전으로 구분한다. 값에는 조회 시작/수신 시각, 실제 확인된 시장 기준 시각·거래일, 원문·환산 진단, 출처·응답 fingerprint, 검증 상태·유형 근거를 함께 보존한다.

같은 실행의 중복은 계획에서 제거하고, 현재 조회 클라이언트는 재전송을 거부한다. 과거 캐시가 존재해도 다른 거래일/시장 시각·환경·근거 버전이면 현재 적격성에 재사용하지 않는다. 임의 TTL이나 날짜가 같다는 사실만으로 최신성을 확정하지 않는다. 기업행동·발행주식 수/상장/유형 변경·정정은 무효화 사유로 설계한다. 캐시 값은 기본적으로 참고 자료이며, 명시적 최신성 정책과 근거 확인이 있어야 검증된 상태로 승격할 수 있다.

## 다음 실제 1회 검증 조건

1. 사용자 별도 승인과 1개 코드·환경·관측 목적을 고정한다. 다른 수집기의 실행/유량과 신규 토큰 발급 위험을 확인한다.
2. 기존 .env/수집기/스케줄러를 바꾸지 않는 별도 실행 계층에 토큰·검증된 CA·TLS/호스트명 검증·정확한 허용 호스트를 연결한다. 이 모듈에 기본 네트워크 실행기는 없다.
3. 최초에는 OAuth 최대 1회 + ka10001 최대 1회(최대 HTTP 2회), 재시도·추가 페이지 없음으로 제한한다. 10종목은 별도 계획의 최대치이지 이번 승인 범위가 아니다.
4. mac 원문·환산·flo_stk·현재가와 HTTP 시각을 안전하게 보존하고 동일 코드/종류주식/시장/관측 시각의 HTS 시총·상장주식 수와 대조한다. flo_stk 단위 충돌과 시총 기준의 공식 답변 또는 독립 근거가 필요하다.
5. 검증 전에는 시총 미확인 UI와 candidate_confirmed=false를 유지한다. 추가 요청이 필요하면 새 승인 전 중단한다.
