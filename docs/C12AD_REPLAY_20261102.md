## 입력과 시점 의미

지원 입력은 기존 분석 입력 JSON, 검증 가능한 저장 C12 보고 JSON(`input_document` 재사용), 시점별 입력 bundle, 명시적 합성 SQLite DB다. bundle 형식:

```json
{"schema_version":"c12-replay-input-v1","documents":["09:40의 기존 입력 객체", "09:45의 기존 입력 객체", "09:50의 기존 입력 객체"]}
```

위 문자열 자리는 실제 입력 객체이며 새로운 데이터 모델을 대체하지 않는다. 복수 입력은 요청 시점에 정확히 대응해야 하며 중복 시점은 거부한다. 기본 09:40/45/50, `--slots 09:50` 등 부분 실행 가능. 15:00은 아직 지원하지 않는다. 비교 함수는 슬롯 사이 변경을 분석과 분리해 두었으므로 향후 오후 전용 기존 판정 경로와 연결할 수 있다. 오전 엔진을 15:00에 임의 재사용하지 않는다.

observed_at 또는 received_at이 기준시각보다 늦은 ranking·security 자료를 제외한다. 해당 시각에 관측했지만 이후 수신된 자료도 사용하지 않는다. 미래 자료 제외 건수와 지연 수신 건수는 원본 레코드 단위다. 거래대금·시총의 시점/단위/출처 유효성은 기존 엔진이 재검증한다. 수집·수신 시각을 앞당기거나 값을 만들어 넣지 않는다.

적격성 결과(candidate_filter)는 정확한 평가시각이 일치할 때만 사용한다. 09:50 마스터 판정을 09:40에 소급하지 않는다. 근거가 없으면 기존 join으로 unmatched 처리하여 보류한다. 따라서 원래 섹터 fixture 단독 입력은 적격성 자료가 없어 보류가 정상이다. 과거 적격성 자료가 없는 단일 저장 보고로 당시 결정을 완전 복원했다고 주장하지 않는다.

분석 generated_at은 결정적 실행을 위해 기준시각+입력 정책의 수신 대기 시간으로 고정한다. 이것은 리플레이의 평가시각이며 실제 수집시각을 생성하거나 바꾸는 것이 아니다. 실제 현재 시각, 임의 ID, 출력 경로는 결과에 넣지 않는다. 같은 입력·날짜·slots에는 같은 결과를 만든다. 출력은 새 파일만 허용하여 입력이나 기존 결과를 덮어쓰지 않는다.

## JSON 진단

각 phase에 섹터 Top3/대표 종목 및 엔진의 동반상승 evidence, 후보별 순위 이력·반복 출현·순위 변화, 거래대금·시총 값/관측·수신 시각/근거, 섹터 태그/관심도 동반 관측, 적격성 결과와 탈락·보류 사유를 담는다. 개별 수치 근거가 없으면 `검증 불가`다. 원래 엔진 보고 전체도 `analysis_report`에 보존해 검증할 수 있다. 섹터 동반 관심과 검증된 동반 상승은 각각 원래 엔진 필드를 유지하며 서로 바꾸지 않는다.

판정은 기존 분석 우선 후보를 `잠정`, 근거 부족을 `보류`, confirmed_excluded를 `제외`로 표시한다. 원래 엔진이 실전 확정 후보를 선언하지 않으므로 새 확정 상태를 만들지 않는다. 검증된 잠정 후보 일부가 있어도 다른 관측 종목의 보류 근거는 함께 표시할 수 있다.

changes에는 섹터 전후 순위, 섹터별 첫 대표 종목 변경, 잠정 후보 진입/이탈, 새로 관측되거나 사라진 코드, 종목별 상태 변화, 관측 누락 및 미래 자료 제외 건수 변화가 나온다. phase 중복 수집 등 분석 오류는 `검증 불가`와 원래의 허용된 오류 코드로 표시하고 조용히 병합하지 않는다. 오류가 난 시점은 비교 불가로 표시한다. 다음 정상 시점 비교는 `from_slot`에 표시한 직전 정상 시점 기준이다.

## 실제 실행한 CLI

PowerShell, 저장소 루트에서 기존 helper로 합성 시점별 입력을 준비했다(병원 자료 아님):

```powershell
New-Item -ItemType Directory -Force reports/c12ad-home-20261102 | Out-Null
.venv/Scripts/python.exe -c "import sys,json;from pathlib import Path;sys.path.insert(0,'tests');from test_c12ac_morning import document;bundle=dict(schema_version='c12-replay-input-v1',documents=[document(s) for s in ('09:40','09:45','09:50')]);Path('reports/c12ad-home-20261102/input.json').write_text(json.dumps(bundle,ensure_ascii=False),encoding='utf-8')"
.venv/Scripts/python.exe -m kiwoom_collector.c12_replay --input reports/c12ad-home-20261102/input.json --date 2026-10-29 --output reports/c12ad-home-20261102/final-1.json
.venv/Scripts/python.exe -m kiwoom_collector.c12_replay --input reports/c12ad-home-20261102/input.json --date 2026-10-29 --output reports/c12ad-home-20261102/final-2.json
```

이미 출력 파일이 있으면 다른 새 출력 이름을 사용해야 한다. Windows 터미널 출력이 깨지면 해당 세션에서 `$env:PYTHONIOENCODING='utf-8'`을 사용할 수 있다. JSON 파일은 항상 UTF-8이다.

실제 합성 결과 요약(관측 중 보류 종목의 근거는 원문 CLI/JSON에 별도 표시):

```text
[ARVIS 오전 리플레이]
날짜: 2026-10-29
09:40 반도체 1위 / 잠정
09:45 반도체 1위 / 잠정
09:50 반도체 1위 / 잠정
```

초기 두 시점은 검증 조건을 만족하는 섹터가 2개, 마지막은 반도체·원전·조선 3개다. Top3 자리를 임의로 채우지 않는다. 두 final JSON의 SHA-256은 모두 `EF84812E03AEBA4B846B1B025EA602DAA0DE435DCA1CE17B8BCB13FE5D2C825D`였다.

원래 fixture 단독 실행도 수행했다:

```powershell
.venv/Scripts/python.exe -m kiwoom_collector.c12_replay --input tests/fixtures/am_sector_briefing_synthetic.json --date 2026-10-29 --output reports/c12ad-home-20261102/plain-fixture.json
```

결과는 세 시점 모두 `섹터 선정 보류 / 보류`, 근거 `종목 적격성 검증 불가`다. 신규 엔진 정책으로 후보를 채우지 않은 의도된 결과다.

합성 DB CLI는 테스트에서 다음 옵션으로 검증했다. 이 단계에서 실전 DB 연결 옵션은 제공하지 않는다:

```powershell
python -m kiwoom_collector.c12_replay --ranking-db SYNTHETIC_RANKING.db --synthetic-db --turnover-db SYNTHETIC_0186.db --evidence SYNTHETIC_MANIFEST.json --capital-json SYNTHETIC_CAPITAL.json --date 2026-10-29 --slots 09:50 --output NEW_RESULT.json
```

위 DB 이름은 형식 예시다. 실전 DB에 `--synthetic-db`를 붙여 사용해서는 안 된다. manifest가 없거나 검증되지 않으면 adapter가 근거를 채우지 않는다. SQLite는 기존 mode=ro/immutable/query_only/authorizer 및 원본 hash 검사 경로로만 읽는다.
