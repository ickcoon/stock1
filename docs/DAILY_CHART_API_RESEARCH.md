# Step 7-B1 — 키움 일봉 API 공식 명세 조사

조사일: 2026-10-28 KST. 공식 공개 문서만 읽었으며 OAuth·시세·주문 API를 호출하지 않았다. 아래의 문서상 확인과 실행 검증은 다르다. 실제 응답은 아직 검증하지 않았다.

## 공식 근거 및 버전 차이

- [ka10081 공식 포털](https://openapi.kiwoom.com/m/guide/apiguide/07/ka10081)
- [ka11081 공식 포털](https://openapi.kiwoom.com/m/guide/apiguide/07/ka11081)
- [공식 REST API 저장소 명세](https://github.com/Kiwoom-Securities/Kiwoom-REST-API/blob/953e5dbff123f437ab4d11a78a95191a685eb51f/kiwoom/_data/kiwoom_api_spec.json) — 조사 시 main SHA `953e5dbff123f437ab4d11a78a95191a685eb51f`.
- [공식 Plugin 정규화 코드](https://github.com/Kiwoom-Securities/Kiwoom-Plugin/blob/7dcf8218f2fc791082decd48932dfdc4276a769e/kw_runtime/normalize.py) — 조사 시 main SHA `7dcf8218f2fc791082decd48932dfdc4276a769e`.

포털은 웹 도구에서 본문을 읽지 못했으나 공개 HTML을 직접 읽고 요청·응답 표를 추출해 확인했다. 공개 HTML은 동적으로 달라질 수 있으므로 영구 버전으로 주장하지 않는다. 공식 GitHub JSON에는 ka10081이 있으나 ka11081 정의가 없었다. ka10081의 응답 수정구분자·수정비율도 포털이 GitHub JSON보다 상세하다. ka11081을 ka10081의 배열 키로 추정하지 않고 포털의 `result_list`를 사용했다. 제3자 SDK와 사용자 이슈는 공식 규칙 확정 근거로 사용하지 않았다.

## 요청·지원 범위

| 항목 | ka10081 | ka11081 |
| --- | --- | --- |
| 이름 | 주식일봉차트조회요청 | 주식일봉차트정규장조회요청 |
| Method / path | POST `/api/dostk/chart` | 동일 |
| 형식 | JSON, application/json;charset=UTF-8 | 동일 |
| 필수 body | `stk_cd`, `base_dt`, `upd_stkpc_tp` | 동일 |
| 기준일 | `base_dt`: YYYYMMDD | 동일 |
| 거래소 요청 코드 | KRX 기본 코드, NXT `_NX`, SOR `_AL` | 동일 |
| 운영 / 모의 도메인 | api.kiwoom.com / mockapi.kiwoom.com | 동일 |
| 모의 범위 | 포털에 KRX만 지원한다고 명시 | 동일 |
| 응답 일봉 배열 | `stk_dt_pole_chart_qry` | `result_list` |

헤더는 authorization, api-id 및 선택적인 cont-yn, next-key이다. 응답 cont-yn이 Y이면 다음 요청에 응답의 cont-yn과 next-key를 전달한다. 이번 구현에는 네트워크 클라이언트나 연속조회 실행기가 없다. 페이지당 최대 행 수와 전체 조회 가능 기간은 확인되지 않았다.

응답 `stk_cd`는 포털 표에 길이 6, 설명은 거래소별 코드로 기재되어 있다. 접미사를 요청해도 응답이 동일 접미사를 반환하는지 실측되지 않았다. 파서는 정확한 문자열 일치만 허용하고 접미사 제거·기본 시장 대입을 하지 않는다. NXT/SOR 응답이 접미사 없이 오면 확인 전까지 거부한다. 현재 종목 코드 문법은 프로젝트 기존 정책인 영숫자 6자리와 선택적 `_NX`/`_AL`이다.

## 응답 필드 및 단위

두 API의 포털 표에서 아래를 확인했다. 필드가 선택 항목으로 기재되어 있으므로 누락은 정상값·0으로 대체하지 않는다.

| 필드 | 문서 의미 | 파서 처리 |
| --- | --- | --- |
| cur_prc | 현재가, 원 | 마감 확정 근거가 있을 때만 종가로 전달 |
| open_pric / high_pric / low_pric | 시가 / 고가 / 저가, 원 | Decimal 가격 및 OHLC 관계 검사 |
| trde_qty | 거래량, 1주 | Decimal, 비음수 정수; 추정 금지 |
| trde_prica | 거래대금, 백만원 | 원본 Decimal 및 ×1,000,000 원 환산 |
| dt | 일자, YYYYMMDD | 실재 날짜·요청 기준일·응답 수신일 검사 |
| pred_pre / pred_pre_sig | 전일 대비 금액 / 방향 기호 | 원문 보존; 현재가에서 전일 종가 역산하지 않음 |
| trde_tern_rt | 거래회전율 % | 원문 보존 |
| upd_stkpc_tp (행 안) | 기업행사 수정구분자, 복수 값 가능 | 요청 body의 0/1과 구별하여 원문 보존 |
| upd_rt | 수정비율 | 원문 보존; 자체 재조정·복원 금지 |

공식 Plugin의 `price()`는 가격 부호를 등락 방향으로 보고 절대값을 사용한다. 파서는 이를 Decimal로 구현하되 원문 부호를 유지한다. 고가·저가가 절대 가격상 뒤집힌 응답은 자동 교환하지 않고 격리한다. 거래량·거래대금의 음수는 절대값으로 덮지 않는다.

공식 Plugin에는 거래량 4,294,967,295 이상 포화값에 대한 방어와 거래대금/종가 추정 경로가 있다. STOCK1은 이 추정을 채택하지 않는다. 해당 값은 미확인으로 두고 판정을 보류한다. 이는 공식 문서상 전 종목 보장 규칙이 아니라 공식 구현에서 확인한 보수적인 방어 정책이다.

## 원주가·수정주가

ka10081 포털은 요청 0=원주가, 1=수정주가를 명시한다. ka11081은 0/1 및 권리발생일 이후 base_dt와 1을 사용하라는 설명을 제공한다. 수정 적용은 base_dt와 권리발생일에 의존하므로 요청 1의 과거 가격을 D0 당시 가격으로 취급할 수 없다. 행의 upd_stkpc_tp는 유상·무상증자, 배당락, 분할·병합, 합병, 감자, 권리락 등의 사건 구분이며 요청의 0/1과 동일한 뜻이 아니다.

ka10081의 upd_rt 표에는 가격과 거래량에 대한 조정·반올림 설명이 있지만 ka11081 표는 그 설명이 비어 있다. 실제 응답 사건일·조정 누적 방식, 원주가 요청의 사후 정정 범위, 거래대금의 수정 적용 여부는 추가 검증이 필요하다. 이번 어댑터는 요청 1을 모두 보류하고, 요청 0도 D0와 가격·거래량·세션 기준이 일치한다는 별도 근거를 요구한다. 수정 가격을 역산하여 D0 스냅샷에 쓰지 않는다.

## Step 7-B2: 1종목·최소 호출 검증 제안

아래는 절차 제안이며 아직 실행하지 않았다. 별도 호출 승인 후 진행한다.

1. 범위를 **KRX 1종목, mock 또는 real 한 환경, 선택한 API 하나, 원주가 0, 완료된 과거 거래일 하나, 일봉 요청 1회**로 고정한다. 정규장 목적이면 ka11081을 우선 검증하되 환경 지원을 먼저 문서와 대조한다. 실패 시 다른 API·환경으로 자동 전환하지 않는다.
2. 기존 승인된 유효 토큰이 있으면 재발급하지 않는다. 없거나 만료되었다면 OAuth는 별도 승인 범위로 명시한다. 무승인 자동 갱신·재시도는 하지 않는다. 기존 요청 간격 정책을 지킨다.
3. 공식 캘린더로 확인한 과거 기준일을 사용한다. 미완성 당일을 피하는 것은 위험 감소일 뿐 봉 확정 근거 자체는 아니다. 정확한 세션 종료·자료 확정·정정 규칙을 확보하지 못하면 파싱 결과만 확인하고 추적 연결은 보류한다.
4. 요청 코드·base_dt·원주가 설정, 실제 요청 시작·응답 수신 KST 시각, HTTP 상태, API ID, cont-yn과 next-key를 남긴다. authorization·쿠키·토큰·계좌정보를 저장·출력하지 않는다. 원본은 운영 DB와 분리된 Git 제외 경로에 저장한다.
5. 한 페이지에서 코드 echo, 배열 키, 역순 날짜, 중복, OHLC 절대 가격, 거래량·거래대금의 단위와 누락을 검증한다. `cont-yn=Y`라도 자동 후속 호출하지 않는다. 필요한 D0·D+1·D+2가 없으면 불충분으로 끝내고 후속 호출은 별도 승인한다.
6. 동일 시장·세션·수정 기준의 공식 HTS/공식 자료와 선택 날짜 OHLCV 및 거래대금을 대조한다. 백만원 표시 정밀도 차이를 원 단위 오차로 오인하지 않는다. 단순 거래대금÷거래량으로 VWAP를 만들지 않는다.
7. 이 1회 호출은 선택 API·시장·환경·날짜의 형식 검증이다. 두 API 비교가 필요하면 **두 번째 API 1회**를 별도 승인하여 같은 조건으로 비교한다. 단일 응답으로 모의/실전·NXT/SOR·수정주가·거래정지·모든 세션을 검증했다고 주장하지 않는다.
8. 근거가 갖춰진 행에만 page/row fingerprint, episode_id, 원본 단위, 세션 기준, market_at, verified_at, D0 기준 호환성이 결합된 ClosingEvidence를 작성한다. 근거가 없으면 만들지 않는다. 과거 수신 자료를 D0 당시 알려진 자료로 소급하지 않고 기존 D0 스냅샷도 수정하지 않는다.
