# Step 7-C6 — 오전 주도섹터 및 관심 후보 문자 브리핑

집 PC 작업 폴더는 기존 `stock1`만 사용한다. 운영 DB, 수집기, Windows 작업 스케줄러,
Step 7-A 추적 엔진과 C4 D0 저장 로직은 변경하지 않는다.

## 현재 범위

`kiwoom_collector.am_briefing`은 합성 fixture 전용 규칙 기반 분석이다. 실데이터 연결이나
자동 발송 등록은 하지 않는다. `real` 환경 표기가 있어도 fixture이면 합성 테스트로 표시한다.
새 AI 호출은 없다. 출력은 관측 기반 관심 후보이며 검증된 매매 전략이나 확정 신호가 아니다.

기존 `am_momentum.analyze`의 시각·환경·시장 검증, 0198 TOP20 관측 완전성,
TOP5/TOP20 횟수, 순위 변화와 섹터 분류를 재사용한다. 기존 엔진에는 섹터 강도
가중 점수가 없으므로 임의 가중치를 추가하지 않고 다음 근거를 순서대로 비교한다.

## 선정 기준

- 09:20, 09:30, 09:40, 09:50 성공 관측과 각 TOP20이 모두 있어야 최종 순위를 만든다.
  누락·실패·이전 거래일·기준 시각 이후 수신 관측은 순위 확정 근거가 될 수 없다.
  09:40 예비 시점에서도 현재 버전은 확정 순위를 보류한다.
- 종목은 TOP5 2회 이상, 마지막 관측 TOP20 잔류가 필요하다. 마지막 TOP5만 허용하면
  최대 5종목밖에 남지 않으므로 섹터별 3종목을 위한 필수 조건으로 삼지 않는다.
- 시총은 **3,000억 원 초과**이다. 정확히 3,000억 원도 제외한다.
- 당일 오전 누적 거래대금 1,000억 이상은 우선 후보, 500억 이상 1,000억 미만은
  예비 후보이다. 500억 미만은 보류한다. 일 마감 거래대금 기준은 적용하지 않는다.
- 등락률은 직접 수집되어 `verified=true`인 양수만 사용한다. 두 가격 간 변화로
  전일 대비 등락률을 추정하지 않는다. 누락·미검증·하락·보합은 이번 주도주 순위에서 보류한다.
- 등락률·누적 거래대금·시총은 당일 기준 시각과 같은 분의 관측이며 기준 시각까지
  수신되어야 한다. 이전 시각 값으로 현재 수치를 채우지 않는 보수적 freshness 정책이다.
  종목명도 동일한 검증을 거치며 없으면 `종목명 미확인`과 코드를 표시한다.
- 동일 섹터 태그 중복은 한 번만 센다. 서로 다른 복수 섹터로 분류된 종목은
  주 섹터를 임의로 택하지 않고 보류한다. 중복 종목·순위·관측 슬롯은 입력을 거절한다.
- 섹터는 위 기준에 맞는 서로 다른 동반 상승 종목 2개 이상이 필요하다.
  우선 후보 2개 미만이면 섹터도 예비 순위로 표시한다. 1개만 남으면 섹터 순위를 보류한다.
- 섹터 비교: 우선/예비 구분 → 적격 종목 TOP20 총 등장 → TOP5 총 등장 →
  동반 상승 종목 수 → 평균 검증 등락률 → 검증 누적 거래대금 합 → 섹터명.
  집계는 적격 종목만 포함하며 같은 종목을 여러 섹터에 중복 합산하지 않는다.
- 섹터 내 종목 비교: 우선/예비 구분 → TOP5 횟수 → TOP20 횟수 → 최근 순위 →
  순위 개선 → 검증 등락률 → 검증 누적 거래대금 → 종목 코드.
  최대 3섹터, 섹터당 최대 3종목이며 빈자리를 다른 미검증 종목으로 채우지 않는다.

## 입력과 출력의 일관성

기존 `am-momentum-fixture-v1` 계약을 사용한다. `securities[code]`에 다음 근거를 추가한다.
각 항목에는 `source_kind=fixture`, `environment`, `market`, `observed_at`, `received_at`,
`verified=true`, `basis`, `value`를 명시한다.

- `names`: 검증된 종목명 문자열.
- `change_pct`: `unit=percent`인 직접 관측 등락률.
- `turnover`: 기존 KRW 항목에 `period=intraday_cumulative` 필수. `daily_close`나 누락은 사용하지 않는다.
- `market_cap`: 기존 `unit=KRW` 항목.

새 보고서 `am-sector-briefing-v1`은 원본 합성 입력, 기존 엔진 결과, 모든 후보의 보류 사유,
섹터 집계와 선정 근거를 보존한다. SHA-256 확인뿐 아니라 보존한 입력으로 결정을
재계산하여 JSON 변조·순위/숫자 불일치를 거절한다.
HTML의 `analysis-data`는 동일 JSON이며 본문 문자는 독립 `format_telegram`의 결과와 같다.
금액은 억 원으로 정확히 환산하며 소수 금액을 정수로 반올림하지 않는다.

```powershell
.\.venv\Scripts\python.exe -B -m kiwoom_collector.am_briefing --fixture tests/fixtures/am_sector_briefing_synthetic.json --name step7c6-synthetic
.\.venv\Scripts\python.exe -B -m kiwoom_collector.telegram_briefing --report reports/step7c6-synthetic.json --html reports/step7c6-synthetic.html
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

첫 명령은 `reports/` 아래 새 `.json`, `.html`, `.txt`만 배타적으로 생성한다.
기존 이름은 덮어쓰지 않는다. 두 번째 명령은 기존 Telegram dry-run 진입점이며 HTTP나
예약 파일을 만들지 않는다. 이 단계에서는 `--send`를 사용하지 않는다.
기존 문자 전송 경로와 수신자 allowlist는 유지한다. 새 포맷은 기존 일자/환경/시장/수신자
중복 방지 예약 공간을 공유하므로 예전 포맷의 실패·불명·완료 예약도 중복 전송을 막는다.

## TTS와 음성 예약 격리

`media_policy.require_legacy_media`는 항상 거절하며 환경변수/CLI 우회 옵션이 없다.
OpenAI TTS의 생성·프로바이더 실행, Telegram 음성 번들/음성 전용 전송, 저수준
`sendVoice`/`sendAudio` 경계를 모두 차단한다. 예약 조회·재시도·새 예약 생성 전에
차단하므로 기존 미해결 예약과 음성 산출물은 원래 위치와 내용 그대로 논리적으로 격리된다.
운영 예약 파일을 이동하거나 초기화하지 않는다. 문자 전용 전송에는 이 차단이 적용되지 않는다.
기존 구현은 삭제하지 않으며 레거시 회귀 테스트만 guard를 명시적으로 patch하여 가짜
HTTP 객체로 진단 경로를 검증한다. 별도 테스트는 patch 없는 실제 정책이 반복 실행과
직접 호출을 차단하고 예약 바이트를 보존하는지 검증한다.
