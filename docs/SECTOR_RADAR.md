# 주도섹터 레이더 v2

[공통 분석 정책](RADAR_ANALYSIS_POLICY.md)에 따라 TOP20은 주도섹터 후보 탐지, TOP5는 매매 후보 검토의 우선 필터로 해석합니다. 조회순위만으로 거래대금·대장주·매수 신호를 확정하지 않으며 거래대금 단위·시점·커버리지 미검증 시 실제 매매 후보 확정을 보류합니다. 아래 기존 계산·정렬·검증 게이트는 유지합니다.

`sector radar`의 인자는 그대로 유지합니다. 선택 날짜(KST)·환경의 **가장 최근 성공한 ka00198 회차**를 메인 화면에 표시합니다. 같은 날짜·환경·qry_tp·test_mode에서 직전 성공 회차를 비교합니다. UTC 오프셋을 KST로 변환한 실제 수집 시각순이며 동시각이면 SQLite 저장 순서(rowid)를 사용합니다. 기본 날짜는 KST 오늘, 환경은 mock이며 `--output`은 필수입니다. 선택된 조회유형과 테스트/운영 구분을 화면 상단에 표시합니다. 최신 회차가 테스트이면 그 테스트 흐름만 비교하며 운영 회차로 자동 전환하지 않습니다.

기존 날짜의 모든 성공 회차와 v1 검증 상세는 하단의 기본 닫힌 `details/summary`에서 확인합니다. 메인은 TOP 3, 부상 섹터, 신규 진입, 섹터 표에 집중합니다. UUID·HTTP 시각·원본 시장 필드·정규화 진단은 펼쳐보기에서만 표시합니다. 외부 스크립트·폰트·CDN 없이 작동하며 CSP로 외부 리소스와 스크립트를 차단합니다.

화면 최종 정리: TOP 3는 섹터명·TOP20 포함 수·거래대금 검증 상태만 표시합니다. 미분류는 TOP 3·부상 순위·주 화면 섹터 표에서 제외하고 메인 하단에 종목 수를 표시하며, 목록은 기본 닫힌 펼쳐보기로 제공합니다. 미분류를 새 섹터에 배정하거나 태그를 수정하지 않습니다. 유효 등락률이 0건이면 `시세 미확인`, 1건 이상이면 `상승 n / 유효 m · 전체 k`로 표시합니다. 섹터 표의 거래대금·평균·적용 수·직전 대비·대표 종목 및 기존 진단 위치는 유지합니다.

최종 정리 회귀 검증(2026-10-23): 기존 358개 + 화면 조건 테스트 8개, 전체 366개가 통과했습니다(71.945초, 실패·오류·건너뛰기 0). 격리 테스트 전후 보호 파일 94개가 동일했습니다. 실제 DB의 읽기 전용 스냅샷으로 1360×900·440×900 브라우저 렌더링을 확인했습니다. PC에서는 분류된 5개 섹터와 하단의 미분류 12종목 안내가 한 화면에 표시되며, 기본 상태에서 섹터 표의 세로 스크롤이 필요하지 않았습니다. 목록 펼치기와 v1 진단 열기도 확인했습니다. 작은 창에서는 세로 스크롤과 표 내부의 가로 스크롤을 사용합니다.

```powershell
python -B -m kiwoom_collector sector radar --date 2026-10-20 --environment mock --db .\data\stock1.db --output .\data\sector-radar-v2-20261020-new.html
Start-Process .\data\sector-radar-v2-20261020-new.html
```

기존 HTML·DB와 같은 파일, 심볼릭 링크는 덮어쓰지 않습니다. 매번 새로운 출력명을 지정해야 합니다. API·인증·Store·마이그레이션을 실행하지 않습니다. 기존 시간별 dashboard와 미분류 workbench는 변경하지 않습니다.

## 산출 지표와 정렬

| 지표 | 계산 기준 |
|---|---|
| 관심도 | 순위 1~20의 유효 종목코드를 중복 제거한 수. 복수 섹터는 각 섹터에서 한 번씩 포함 |
| TOP5 / TOP10 | 각 섹터 구성 종목 중 순위가 5 / 10 이하인 수 |
| 직전 대비 | 현재 종목 수 − 같은 비교 범위의 직전 종목 수. 비교가 없으면 null/비교 대상 없음 |
| 부상 섹터 | 종목 수가 증가한 섹터. 증가 수 → 현재 종목 수 → TOP5 → TOP10 → 이름 순, 임의 점수 없음 |
| 신규 진입 | 현재 고유 코드 집합 − 직전 고유 코드 집합. 현재 순위순. 비교가 없으면 0으로 만들지 않음 |
| 상승 확산 | 기존 assess()를 통과한 등락률 > 0 종목 수 / 유효 등락률 종목 수. 하락·보합·제외도 별도 표시 |
| 거래대금 합 | 같은 회차의 최신 단일 ka10095 배치에서 단위·필드·시점 검증을 통과한 코드별 누적 거래대금 합 |
| 평균 거래대금 | 검증된 부분합 / **적용 종목 수**. 전체 종목 수로 나누지 않음 |
| 커버리지 | 거래대금 적용 종목 수 / 해당 섹터 관심 종목 수. 전체 TOP20 집계에서는 코드 중복 제거 |

거래대금은 장중 누적액이며 구간 거래대금·회차 간 증가분이 아닙니다. 이전 회차·이전 시도·다른 API·다른 환경 값을 더하거나 누락분을 채우지 않습니다. 최신 배치가 비어 있거나 실패해도 과거 배치로 되돌리지 않습니다. 완료된 일부 관측은 진단에서 확인할 수 있으나 running/error/interrupted 배치의 금액은 집계하지 않습니다. 같은 배치의 순차 요청은 동시 관측이 아닙니다. 기존 assess()의 같은 날짜·±300초 조건과 배치 내 요청 완료/API 시각 범위 300초 이하를 보수적으로 적용합니다. 정밀 동기화나 체결시각 보장은 아닙니다.

금액 단위가 독립 검증되고 **현재 TOP20 고유 종목 전체가 유효한 거래대금을 가질 때만** 거래대금을 주 정렬 기준으로 사용합니다. 동률이면 종목 수 → TOP5 → TOP10 → 이름 순입니다. 일부만 검증되면 알려진 부분합·평균·적용 수는 표시하되, 누락에 따른 순위 왜곡을 막기 위해 표는 관심도순으로 표시합니다. 임의의 복합 가중치는 없습니다. 미분류는 TOP 3·부상 순위·섹터 표에서 제외하고 하단 목록으로 분리하지만 전체 고유 종목 수, 신규 진입 계산 및 전체 거래대금 커버리지의 분모에는 유지합니다. 내부 집계와 v1 진단의 미분류 자료도 보존합니다. TOP20 표본 합계는 시장 전체 거래대금이 아닙니다.

### 단위 검증 게이트

현재 normalize_quote()의 `turnover_source_unit=million_KRW`는 공식 명세에 따른 환산 선언입니다. **실전 단위의 실측 검증 완료 표시가 아닙니다.** 기존 데이터는 수정·재분류하지 않으며 거래대금 기반 주도섹터 확정을 보류합니다. 이때 관심섹터 TOP 3와 검증된 등락률은 계속 표시됩니다.

Radar v2는 기존 normalized_json의 선택 메타데이터 `turnover_unit_status="verified"`와 비어 있지 않은 `turnover_unit_evidence`를 독립 단위 검증 근거의 계약으로 읽습니다. 기존 version/SPEC_VERSION/API/원 단위 환산값 검증도 함께 필요합니다. **현재 수집기나 quote-fields-test는 이 두 필드를 생성하지 않습니다.** 이번 작업은 검증 근거를 등록하는 기능·DB 변경을 추가하지 않습니다. 테스트의 verified 값은 가상 데이터뿐입니다. 실제 검증 근거의 검토·등록 방식은 후속 승인 범위에서 결정해야 합니다. 기존 값을 수동으로 verified로 바꾸는 운영 절차를 권고하는 뜻이 아닙니다. mock 검증 표시는 실전 검증을 증명하지 않습니다.

v2 주 화면에서는 시세와 순위의 test_mode 및 배치 test_mode가 모두 같은 관측만 사용합니다. 기존 명시적 시세 테스트가 운영 순위에 연결된 이력은 v1 진단에서 보존하되 v2 집계에는 포함하지 않습니다. 날짜·환경·회차·종목코드·순위·API 연결 규칙과 assess() 자체는 변경하지 않았습니다.

## 보존된 v1 검증 규칙과 진단

- 파랑: 조회순위상 인기. 관심 수와 TOP5/TOP10 포함 수는 순위 데이터만 사용합니다.
- 초록: 시세 상승이 확인된 주도주 후보. 시점이 일치하고 검증된 등락률이 양수인 경우입니다.
- 섹터 강도는 유효 관측의 상승·하락·보합 종목 수로 표시합니다. 분석 제외 수를 별도로 표시하며, 누락 시세를 보합/0으로 처리하지 않습니다.
- 시점 일치 조건: 순위 수집 시각, 요청 완료 시각, API 날짜+시각이 모두 존재하고 같은 KST 날짜이며, 순위 대비 요청 완료와 API 시각의 차이가 각각 ±300초 이내입니다. API 체결 시각이 오래된 경우도 보수적으로 제외합니다. 300초는 v1의 명시적 비교 허용 기준이며 동시 체결을 보장하지 않습니다.
- 10월 20일 순위에 10월 22일 사후 조회 시세를 붙이면 `시점 불일치·분석 제외`입니다. 원래 관측 시각과 시간 차이를 그대로 보여줍니다.
- 검증된 등락률은 저장된 normalized_json version=1, 지원 API, 기존 SPEC_VERSION 일치가 필요합니다. 과거 normalized_json 미보유 행을 재해석하거나 DB에 저장하지 않습니다.
- 가격 부호 미확정은 별도 표시합니다. 후보는 등락률 기준이며 가격 자체의 부호를 확정하거나 절댓값으로 변환하지 않습니다.
- 거래대금은 검증된 normalized_json의 turnover_source_unit=million_KRW 및 유한한 비음수 turnover_won만 원 단위로 표시합니다. 원본 백만원 값을 다시 변환하지 않습니다. 단위/값 미검증은 별도 표시하고 합산하지 않습니다.
- 복수 API/시도는 시점이 일치하는 유효 관측을 우선하고 그중 요청 완료가 최신인 것을 선택합니다. 유효 관측이 없으면 가장 최근 것을 보여줍니다. 모든 관측은 상세 근거에 남습니다.
- 현재 stock_sectors의 기존 태그와 출처를 재사용합니다. 자동 테마 생성은 없으며 복수 섹터를 허용합니다. 태그 없는 종목은 미분류로 표시합니다. 현재 태그를 과거 회차에 적용한다는 한계가 있습니다.

DB는 mode=ro + query_only + 읽기 트랜잭션으로 접근합니다. Store/마이그레이션/자격 증명/API 호출이 없으며 시세 테이블 없는 구형 DB도 시세 미수집으로 처리합니다. HTML은 내장 CSS와 네이티브 details만 사용하여 네트워크·스크립트 없이 열립니다. 기존 dashboard/workbench/스케줄에는 연결하지 않습니다.

## 시총별 섹터 확산 분석: 조사만 수행

기준 [키움 공식 명세 JSON](https://github.com/Kiwoom-Securities/Kiwoom-REST-API/blob/953e5dbff123f437ab4d11a78a95191a685eb51f/kiwoom/_data/kiwoom_api_spec.json)의 ka10095 응답 목록에는 `mac`(시가총액, 억원), `stkcnt`(주식수, 주)가 정의되어 있습니다. ka10001에도 `mac`(억원)이 있습니다. 현재 BatchQuoteClient.fetch_quotes()의 필드 허용 목록과 normalize_quote(), stocks 테이블에는 시가총액 이력이 없습니다. 공식 응답 필드의 존재가 실전 응답 제공·정확성 검증을 뜻하지는 않습니다. 기존 수집이 버린 필드는 사후 복원하지 못합니다.

후속 최소안은 별도 승인 후 ka10095의 기존 요청 응답에서 mac을 허용 목록으로 보존하여 추가 API 없이 수집 가능한지 먼저 소규모 검증하는 것입니다. ka10001 별도 조회는 ka10095 제공 여부 확인 후 필요할 때만 검토합니다. 같은 회차·환경·시장 구분과 단위 검증 상태를 가진 시총 스냅샷이 필요하며, 과거 회차에 현재 시총을 대입하지 않아야 합니다. 원시 시총과 기준일을 보존하고 구간 경계는 그 다음에 정해야 합니다.

향후 표본 내 대형/중형/소형별 관심 수·유효 상승 수·거래대금 커버리지를 비교할 수 있습니다. TOP20만으로 시장 전체의 시총별 상승 확산율을 추정할 수는 없습니다. 시장 전체 분모가 필요하면 별도 종목 유니버스·기준일·분류 데이터 계획이 먼저 필요합니다. 소형주를 자동 제외하는 규칙은 추가하지 않았습니다. 이번 단계에는 시총 수집·분류·계산·화면·DB 변경을 구현하지 않았습니다.
