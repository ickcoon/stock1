### 코드 검증

6자리 숫자/대문자 영숫자 코드를 보존한다. 실제 관측의 `0013Y0` 등 영문 포함 코드도 허용한다. 짧은 코드나 정수를 임의로 0-padding하지 않는다. 7자리 `A` 접두어는 해당 6자리 대상이 공식 마스터에 있을 때만 해석한다. 6자리 자체가 `A`로 시작하는 코드는 그대로 유지한다. 현재 `stex_tp=1` 범위에서 `_NX`·`_AL`을 몰래 제거하지 않는다. 시장은 코드 앞자리로 추정하지 않고 공식 `KOSPI`/`KOSDAQ`을 사용한다. 실제 관측 코드는 전부 6자리 구문 검증을 통과했다.

3. 테마 기록의 당시 수신 시각과 영구 소속이 검증되지 않았다. 실제 코드 매핑·새 공식명/약칭 추가 연결은 합성 테스트로만 검증했다.
4. 0186 런타임 금액 단위·누적 기준, 동일 시각의 검증된 시총·유동성, 09:45 0186이 부족하다.

## G. C15-10 주도권 변화 추적 최소 설계

### 기존 저장 상태

운영 `stock1-real.db`에는 `collections`, `ranking_records`, 종목/테마 태그 표가 있고, 0186 DB에는 run/page/row 원본이 있다. KRX DB는 일별 OHLCV·종목 식별, 테마 DB는 과거 테마 관측을 보존한다. **어느 DB에도 C15-8의 날짜·슬롯별 섹터 점수·상승 종목 수 이력 표는 없다.** 기존 운영 workflow의 별도 tracking JSON은 종목 episode 용도이며 C15 관측 점수 상태 이력이 아니다.

C15-8 개발 미리보기 JSON에는 기준시각·TOP3 점수·상승 수가 있지만 TOP3 밖의 다종목 상승 테마 점수는 보존되지 않았다. 이번에는 기존 엔진에서 이미 계산한 전체 순위 결과를 보존하고 `morning_leadership.tracking_observations`를 출력한다. 실제 출력 행은 09:40 42테마, 09:45 22테마, 09:50 43테마다. DB 마이그레이션·운영 저장 훅·상태 전이 엔진은 추가하지 않았다.

### 최소 관측 레코드

출력에는 다음이 있다: 날짜/슬롯/기준시각/판정 컷오프, 테마명, 전체 계산 점수와 구성 요소, 점수 대상 관측 수, 상품 제외 전 매핑 관측 수, 원시 보고 상승 수, 매핑된 등락률 확보 수, 종목 코드 목록, 소스 스냅샷 해시, 관측 모집단 해시, 테마 연결 해시, 가중치 해시, 매핑 버전, 공식 근거 기준일, 매핑률, 부분/미확인 상태. 확인할 수 없는 점수는 NULL로 두며 0으로 채우지 않는다. `transition_state=not_evaluated`이며 외부 흐름 요약은 점수 입력에 포함되지 않는다.

C15-10에서는 먼저 이 JSON을 개발 경로에 append-only로 보존하는 방식만 사용해도 된다. 필요할 때만 `(날짜, 슬롯, 테마, 원본 스냅샷 해시, 정책 버전)` 키를 가진 개발용 SQLite 표로 옮긴다. 운영 DB 변경은 별도 작업이다.

### 비교 순서와 상태 제안 — 이번에 구현하지 않음

1. 수신 컷오프·가중치·매핑 버전·주문시장 범위를 확인한다. 서로 다른 버전은 같은 기준으로 별도 재현 가능한 경우에만 비교한다. 이후에 얻은 이름/유형/테마를 과거의 당시 사실로 소급 적용하지 않는다.
2. 날짜 간 비교는 같은 시각끼리, 장중 비교는 별도 시계열로 관리한다. 관측 코드 교집합을 따로 비교하거나 모집단이 달라진 정도를 표시한다. 미관측·미분류·미확인 시각은 약세 값으로 채우지 않는다.
3. **신규 부상:** 최근 유효 비교 시점에서 강세권 밖이었다가 강세권에 진입하고 기존 동반 상승 최소 2종목 근거가 있는 경우를 후보로 본다.
4. **강세 지속:** 여러 유효 비교 시점에서 강세권과 동반 상승 수·강도를 유지하는 경우다. 시작은 최소 2개 비교 시점으로 제안하되 창 길이·강세권/유지 임계값은 별도 설정·검증한다.
5. **주도력 약화:** 비교 가능한 종목 범위에서 상승 수·강도와 관심이 감소하는지 확인한다. TOP3 밖으로 밀렸거나 데이터에서 사라진 사실 하나만으로 약화로 확정하지 않는다.
6. **판단 보류:** 0186 없음, 유형/테마 식별 부족, 시각 이후 자료, 정책/범위 불일치, 부분 수집 편향을 해결하지 못한 경우다. 현재 테마 시점 검증 한계 때문에 엄격한 시점 기준의 상태 확정은 보류해야 한다.
