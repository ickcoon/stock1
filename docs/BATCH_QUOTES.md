# ka10095 2종목 검증 단계 (2026-10-22)

후속 독립 TOP20 실행과 dry-run은 [TOP20 분할 시세 설명](TOP20_QUOTES.md)에 있습니다. 기존 quote-batch-test는 2종목 테스트로 유지합니다. 사용자가 모의 2종목 조회·저장 성공을 보고했으며, 이는 해당 요청의 실증 결과입니다.

## 확인된 명세와 한계

근거는 [키움 공식 명세의 프로젝트 기준 커밋](https://github.com/Kiwoom-Securities/Kiwoom-REST-API/blob/953e5dbff123f437ab4d11a78a95191a685eb51f/kiwoom/_data/kiwoom_api_spec.json)입니다. 확인일 2026-10-22. 최신 포털 상세표와의 전면 대조는 완료하지 않았습니다.

- `지정종목 정보요청(ka10095)`: `POST /api/dostk/stkinfo`, `api-id: ka10095`, Bearer 인증. `stk_cd`에 `005930|000660`처럼 `|`로 구분합니다.
- 응답 목록 `atn_stk_infr`, 종목 식별 `stk_cd`; 현재가 `cur_prc`, 등락률 `flu_rt`, 거래량 `trde_qty`, 거래대금 `trde_prica`, 시가/고가/저가 `open_pric`/`high_pric`/`low_pric`. 모두 선택적인 문자열입니다.
- 날짜 `dt`(YYYYMMDD), 체결시간 `cntr_tm`(HHmmss), 호가시간 `bid_tm`(HHmmss)을 구분해 보존합니다. ka10007의 `date`/`tm`으로 임의 개명하지 않습니다.
- 가격 단위 원, 거래량 주, 거래대금 **백만원**, 등락률 %입니다.
- 요청 필드 길이는 20으로 표기되어 있으나 **최대 종목 수는 확인되지 않았습니다**. 이 구현은 2종목·연결 문자열 길이 20 이하만 허용합니다. TOP20 일괄 요청 한도를 20개나 100개로 추정하지 않습니다.
- 모의 도메인은 명세에 존재합니다. **사용자가 Windows 병원 PC에서 ka10095 2종목 조회·저장 및 TOP20의 나머지 18종목 9회 요청 성공을 확인했습니다**(미전송 0건, 종목별 성공, issues 없음). 이는 해당 종목·시점의 실증 결과이며 모든 상품·시간대 지원을 보장하지 않습니다. 오류 8104 시 `mock_unsupported`로 남기고 실전 또는 ka10007로 자동 전환하지 않습니다.
- HTTP 오류, 숫자 `return_code`, 잘못된 응답 객체·목록, 연속조회 요구를 실패 처리합니다. 서버 메시지·토큰·헤더는 저장하지 않습니다. 오류 분류 8104, 1700/1701/1702는 프로젝트에 기록된 공식 오류 구현을 근거로 합니다.
- [공식 REST 서비스 안내](https://openapi2.kiwoom.com/intro?dummyVal=0): 국내 조회 TR 계좌별/토큰별 초당 5회, 모의 동일 TR 초당 1회. 장시간 누적 제한 및 ka10095 별도 제한은 미확인입니다. 기존 1초 간격 정책을 유지하며 다른 프로세스 합산 유량은 조정하지 못합니다.

## 실행 — 사용자 검토 후 명시적으로 호출

다음 명령은 **실제 모의 API를 호출하고 지정 DB를 마이그레이션·저장**합니다. 구현 검증에서는 실행하지 않았습니다. 운영 DB 변경·실호출은 사용자의 별도 확인 이후에만 진행합니다. 백업을 확보하고, 같은 mock 환경의 성공 ka00198 회차에 두 종목이 있는지 확인하세요.

```powershell
# 사용자 PC의 Windows Python 3.11 환경에서 먼저 오프라인 테스트
py -3.11 -m unittest discover -s tests -p test_batch_quotes.py -v
py -3.11 -m unittest discover -s tests -v

# 실제 모의 호출용 예시 — UUID를 선택한 기존 회차로 교체
py -3.11 -m kiwoom_collector quote-batch-test `
  --collection-id "기존-mock-회차-UUID" --environment mock --limit 2 `
  --db data/stock1.db
```

패키지가 .venv에 설치되어 있다면 `py -3.11` 대신 `.\.venv\Scripts\python.exe`를 사용합니다. 기존 `.env`와 프로세스 환경의 `KIWOOM_ENV=mock`, 모의 키·권한·IP를 확인하세요. 환경 일치 검증은 기존 quote-test와 같습니다. 실전은 명시적인 `--environment real`과 실전 키·회차가 모두 일치해야 하며 자동 전환하지 않습니다.

인증 최대 1회와 ka10095 요청 최대 1회입니다. 자동 재시도·연속조회는 없습니다. 응답 순서와 무관하게 **종목코드 완전 일치**로 연결합니다. 없는 종목은 `missing_stock`, 같은 코드 중복은 `duplicate_stock_code`, 요청하지 않은 코드·코드 없는 행은 전체 실패입니다. 정상 종목과 누락·필드 오류가 섞이면 부분 성공입니다. 접미사를 제거해 KRX/NXT/SOR를 섞지 않습니다.

중복 키는 회차·순위·API·테스트 구분입니다. ka10007과 ka10095는 충돌하지 않습니다. 실패·중단·running도 선점을 유지하므로 같은 명령 재실행은 HTTP를 반복하지 않습니다. 다시 실험하려면 새로 수집한 회차를 선택하세요. 강제 재시도·과거 관측 덮어쓰기 옵션은 없습니다. 중복 생략 종료 코드 0은 이전 관측 성공을 뜻하지 않습니다.

## 저장 구조와 이전 버전 마이그레이션

실제 로컬 DB의 메모리 복사본에서 기존 quote_batches/quote_observations와 삼성전자 원본 8개 값이 사용자 보고와 일치함을 확인했습니다. date/tm 및 HTTP 시각이 존재했고 정규화 열은 없었습니다. 운영 DB 파일은 변경하지 않았습니다.

기존 1단계에는 quote_requests가 없었으므로 이번에 추가합니다. ka10095의 한 HTTP 요청과 여러 관측의 연결은 batch_id로 표현합니다. 요청 대상 코드, HTTP 시각, 숫자 상태, 종목별 허용 필드와 진단을 저장합니다. response_json은 응답 바이트 원본이 아닌 **요청 종목별 허용 필드 보존본**입니다. 기존 ka10007 요청 이력을 추정해 채우지 않습니다.

기존 두 시세 테이블의 API CHECK가 ka10007만 허용하므로, 해당 구버전에 한해 트랜잭션 안에서 시세 테이블을 재구성하여 ka10095도 허용합니다. 기존 열과 행을 그대로 복사하고 외래 키를 유지합니다. collections/ranking_records/종목·테마·일정 테이블은 재작성하지 않습니다. quote_observations에 nullable `normalized_json`을 추가합니다. 구 관측의 정규화는 소급 계산하지 않으며 NULL로 둡니다. 재실행 시 재구성하지 않습니다. 오류 발생 시 이름 변경·복사·새 스키마를 모두 롤백하는 테스트를 포함합니다.

이번 마이그레이션은 명령을 사용자가 실행할 때만 적용됩니다. 기존 수집기의 초기화 경로와 정기 일정에는 연결하지 않았습니다. 시세 전체 실패도 순위 성공을 바꾸지 않습니다. 모든 시세는 계속 test_mode=1입니다.

## 원본과 보수적 정규화

사용자 및 로컬 DB에서 확인된 원본은 다음과 같습니다. 이 값들은 임의 생성한 라이브 응답이라고 주장하지 않습니다.

`cur_prc=-213500`, `flu_rt=-4.47`, `trde_qty=11224535`, `trde_prica=2440411`, `open_pric=-221500`, `high_pric=+226000`, `low_pric=-212000`.

공식 가격 설명은 ‘원, 부호가 포함된 숫자’까지 확인했습니다. 그러나 각 가격 부호의 정확한 기준과 절댓값 변환을 명시한 공식 근거는 확인하지 못했습니다. 다른 API의 주문구분 색상 설명을 시세 가격에 적용하지 않습니다. 따라서 원본 부호를 유지하고 `current_price_won`, `open_price_won`, `high_price_won`, `low_price_won`은 NULL, `price_status=unverified_sign_semantics`로 둡니다.

공식 단위와 숫자 구문을 확인한 값만 정규화합니다. 등락률은 부호 있는 Decimal 문자열, 거래량은 음수가 아닌 정수, 거래대금은 백만원→원 단위 Decimal 문자열입니다. 예시 거래대금은 `2440411000000`원입니다. float를 쓰지 않습니다. 누락·잘못된 자료형·음수 거래량/거래대금·지수 표기·NaN은 NULL입니다. 원본은 수정하지 않습니다.

시각은 다음을 구분합니다.

1. 부모 collections.collected_at: 과거 순위 수집 시작 시각.
2. quote_batches.started_at/finished_at: 이번 시세 실행 시각.
3. request_started_at/request_finished_at 및 quote_requests.started_at/finished_at: 인증·대기 제외 HTTP 시작/종료.
4. 원본 date/tm 또는 dt/cntr_tm/bid_tm: 서버 제공 일자·시각.

보고서의 `temporal_relation=current_quote_for_historical_ranking`은 과거 회차의 종목을 현재 조회했다는 뜻입니다. 과거 가격으로 소급 해석하지 않습니다. 서버 시각은 요청 시각으로 덮어쓰지 않으며 최신성·동시성 보장은 실호출 검증 과제로 남깁니다.
