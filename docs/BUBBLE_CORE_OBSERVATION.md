# TOP5 핵심주 관찰 패널 (Step 4-F)

[공통 분석 정책](RADAR_ANALYSIS_POLICY.md)의 TOP20 섹터 탐지 → TOP5 핵심 종목 우선 검토 → 거래대금·시세·유동성 검증 후 매매 후보 분류 원칙을 따른다. 이번 기능은 조회 관심도 관찰 패널이며 매매 후보 확정·대장주 판별·거래대금 순위를 만들지 않는다.

```powershell
python -B -m kiwoom_collector.bubble_core --date 2026-10-20 --environment mock --db data/stock1.db --output data/bubble-core-20261020-new.html
python -B -m kiwoom_collector.bubble_core --date 2026-10-26 --environment mock --db data/stock1.db --output data/bubble-core-20261026-new.html
```

별도 모듈을 추가하며 기존 v2·v3·Bubble v1·타임라인·TOP3 레이아웃의 코드와 기본 출력은 유지한다. 기존 `bubble_layout`의 보고서·배치·HTML을 재사용하고 새 파일에서 섹터 상세 패널을 확장한다. TOP3/TOP2, 버블 면적·색상·위치, 타임라인 선택, 표 보기와 전체 섹터 목록을 바꾸지 않는다. 지도 밖 섹터도 같은 패널을 볼 수 있다. 기존 파일·심볼릭 링크·DB 경로는 덮어쓰지 않는다.

## 집계와 상태

- 동일 KST 거래일·환경·ka00198·qry_tp=1·test_mode=0·성공 관측만 사용한다. 각 프레임은 선택 시각 및 동일 시각의 저장 순서까지의 prefix다. 다른 환경·유형·테스트·실패·미래 회차를 포함하지 않는다.
- 코드별로 회차당 한 번 집계한다. 중복 코드는 유효 조회순위 중 가장 앞선 순위를 사용한다. 다중 태그가 있어도 개별 종목의 TOP5/TOP20 등장 횟수는 한 번이며 섹터 간 같은 값을 재사용한다.
- 현재 순위, 직전 성공 회차 순위, TOP5 출현 횟수/성공 관측 수, 현재 TOP5 연속 횟수, 선택 시각까지 당일 최고 조회순위(최솟값)를 표시한다. 하루 전체의 미래 최고 순위를 미리 사용하지 않는다.
- TOP5 신규/유지/이탈은 직전 성공 회차와 비교한다. 첫 회차는 비교 불가다. TOP5 이탈 후 6~20위이면 TOP20 유지를 함께 표시한다. 표본이 불완전하여 이전/현재 TOP5 또는 TOP20의 부재를 확정할 수 없으면 비교 불가·관측 미확인으로 표시한다. 직접 관측된 현재/직전 순위는 보존한다.
- TOP5 연속은 현재부터 거꾸로 세되 두 회차의 명시적 scheduled_at이 기존 10개 예정 슬롯의 인접한 시각이고 실제 수집 시각도 해당 연결을 뒷받침할 때만 잇는다. 10→11→12시는 인접 예정 회차다. 09:30→09:50의 중간 누락, 일정 미기록·동일 슬롯·비정기·순서 역전·이전 회차가 다음 슬롯 이후까지 지연된 경우에는 연속을 끊는다. 현재 TOP5면 1부터 다시 시작하고 TOP5 밖이면 0이다. 예정 회차를 실제 시각에서 임의 추정하지 않는다.
- 누락을 건너뛰어 직전 성공 회차와 비교한 TOP5 유지는 가능하지만, 연속 횟수는 새로 시작한다. 화면에 연결 확인/누락/미확인 사유를 표시한다. 기존 v3의 성공 관측 기준 섹터 연속 수와는 별도 지표다.

## 화면과 검증 상태

선택 섹터의 현재 TOP5를 패널 상단에 조회순위순으로 표시한다. 종목명·현재/직전 순위·TOP5 횟수·연속·당일 최고와 시세/거래대금/유동성 검증 상태를 제공한다. TOP5 이탈, 나머지 TOP20 보조 관찰(반복 등장 수 포함), 과거에만 등장한 종목은 접힌 목록이다. 기존 섹터 요약·종목 표·시세/금액 근거는 '기존 섹터 상세·검증 근거'에서 그대로 확인한다.

**조회 관심도 기반 핵심 관찰종목 — 매매 후보 미확정** 문구를 표시한다. 시세·금액은 기존 v2/v3 검증 결과만 읽으며 현재 종목이 없으면 이전 시세를 현재 검증 상태로 재사용하지 않는다. 모의 검증은 모의임을 표시한다. 유동성 검증은 미구현이므로 기존 금액·시세가 유효해도 매매 후보를 확정하지 않는다. 개별 금액은 거래대금 순위가 아니며 순위·최고·색상은 모두 조회 관심도다. 새 점수·가중치는 없다.

새 패널은 기존 검증에 더해 요청 완료 시각과 API 시각이 모두 선택 회차의 순위 수집 시각 이하인지 확인한다. 순위 직후 수 초 뒤에 완료된 같은 회차 시세도 선택 시각 이후 자료이므로 새 패널에서는 미확인으로 유지한다. 기존 섹터 진단은 종전의 동일 회차·시점 허용 범위를 유지하며 선택 이후 시세도 포함할 수 있음을 별도로 안내한다. 기존 시세 판단 코드는 수정하지 않는다.

PC 1360×900에서는 기존 우측 패널, 모바일 390×844에서는 지도 아래 패널을 사용한다. 모바일의 '선택 섹터 상세로 이동'과 접힌 목록은 기존 네이티브 동작을 유지한다. HTML/CSS·SVG만 사용하고 외부 서버·스크립트·CDN은 추가하지 않는다.

## 읽기 전용과 검증

운영 DB는 기존 timeline.report의 mode=ro + query_only + 읽기 트랜잭션과 SQLite Backup API를 통해 읽는다. 집계는 메모리에서만 수행한다. 운영 DB·스키마·수집 엔진·.env·API 설정·인증정보·10회 일정·TOP20 시세 연동을 변경하지 않는다. API/OAuth·Store·import·마이그레이션을 호출하지 않는다. qry_tp=4·Calendar는 추가하지 않는다.

```powershell
python -B -m unittest discover -s tests -p test_bubble_core.py -v
python -B -m unittest discover -s tests -v
git diff --check
```

회귀 검증에는 첫/중간/마지막 prefix, TOP5 진입·유지·이탈과 TOP20 구분, 다중 태그·중복 코드, 누락·일정 불명·동일 슬롯·지연, 불완전 표본, 환경/유형/모드/미래 분리, 최신 배치 검증, 기존 출력 불변, 파일 보호, CLI·PC/모바일 브라우저를 포함한다. 운영 DB 스냅샷의 10월 20일 10회와 10월 26일 5회 전체 프레임 및 화면 캡처는 로컬 data에 별도 보관한다. 실전 거래대금·시세·주문 규모 대비 유동성과 다른 브라우저·보조공학 검증은 후속 범위다.
