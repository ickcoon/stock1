# Sector Radar v3 — 읽기 전용 장중 관심 변화

[공통 분석 정책](RADAR_ANALYSIS_POLICY.md)에 따라 TOP20은 섹터 탐지, TOP5는 매매 후보 검토의 우선 필터로 사용한다. TOP5 반복과 검증된 섹터 동반 상승·거래대금을 각각 확인하며 순위만으로 후보를 확정하지 않는다. 기존 진입/유지/이탈은 TOP20 집합 기준이며 TOP5 전용 상태 표시·후보 확정 기능을 새로 구현하지 않는다.

v2와 수집 엔진을 그대로 두고 `kiwoom_collector.radar_v3` 모듈로 실행한다. 기본 대상은 동일 KST 날짜·환경·`qry_tp=1`·`test_mode=0` 성공 회차다. 운영 DB를 `mode=ro + query_only + 읽기 트랜잭션`으로 열고 SQLite Backup API로 WAL을 포함한 임시 스냅샷을 만든다. v2의 회차 로더·중복 제거·시세 검증·진단을 그 스냅샷에 재사용한다. 임시 DB 연결은 닫은 뒤 제거한다. Store·마이그레이션·API·인증을 실행하지 않는다.

```powershell
python -B -m kiwoom_collector.radar_v3 --date 2026-10-20 --environment mock --db data/stock1.db --output data/sector-radar-v3-20261020-new.html
python -B -m kiwoom_collector.radar_v3 --date 2026-10-26 --environment mock --db data/stock1.db --output data/sector-radar-v3-20261026-new.html
```

`--output`은 새 HTML 경로여야 하며 기존 파일·심볼릭 링크를 덮어쓰지 않는다. `--date` 생략 시 KST 오늘이다. 테스트 흐름을 보려면 `--test-mode 1`을 명시한다. 다른 조회 유형이 더 늦게 저장돼도 v3 장중 메인을 대체하지 않는다. 기존 `python -m kiwoom_collector sector radar ...`는 그대로 v2를 출력한다.

메인 화면은 관측 증가·감소 섹터를 나란히 표시하고, 진입/유지/이탈 수, 반복 등장 섹터, TOP20·TOP5 증감과 지속성 표를 제공한다. 현재 관심 상위 3개, 증가·감소, 지속 섹터 순으로 중복 없이 최대 6개 행을 선정하며 전체 목록은 펼쳐보기로 보존한다. 진입·이탈은 각각 대표 2종목을 표시하고 전체 진입·유지·이탈 및 반복 종목은 펼쳐볼 수 있다. 이탈 종목의 순위·시세는 직전 관측이다.

현재 섹터가 0종목이 돼도 감소로 남긴다. 최초 관측에는 변화량·신규 진입을 만들지 않는다. 출현 횟수 분모는 실제 성공 관측 수이며 예정 10슬롯이나 시간 점유율이 아니다. 지속성은 관측 연속 수·TOP5 출현·관심 TOP3 출현으로 표시하며 가중 점수는 없다. TOP3 반복은 금액과 독립적인 v2 관심도 정렬을 사용한다.

실제 회차 간격을 표시하고 중간 예정 슬롯의 미관측/미완료 상태를 안내한다. 당일 관측 흐름은 PC 핵심 표를 한 화면에 유지하기 위해 기본 접힘이다. 펼치면 최대 10개 최근 관측의 TOP20/TOP5와 예정 슬롯 상태를 보이며, 다시 전체 섹터·모든 성공 관측을 펼칠 수 있다. 실패·running·기록 없음·미래 예정은 성공 0회차로 채우지 않는다. `scheduled_at` 없는 관측은 임의 슬롯에 배정하지 않는다. 같은 시각은 저장 rowid 순이다.

미분류는 관심 순위·지속성 순위에서 제외하지만 전체 고유 종목·교집합·진입·이탈 분모에 남는다. 다중 섹터는 각 섹터 내 코드 1회, 전체는 코드 1회로 센다. 섹터 합계가 전체 고유 수와 다를 수 있다. 현재 태그를 같은 보고서의 모든 과거 관측에 적용하며 당시 분류 이력을 재현하지 않는다. 바이오·제약·바이오 자동 통합은 없다.

불완전 TOP20은 실제 고유 수를 표시하고 감소·순환 판단 보류를 안내한다. 등락률·거래대금은 v2의 시점·최신 단일 배치·모드·단위·커버리지 검증을 재사용한다. 검증이 없는 값을 0으로 바꾸거나 과거 값으로 보충하지 않는다. 상세에는 섹터별 검증 금액·부분합·적용 종목당 평균과 시세 진단을 보존한다. 실전 검증되지 않은 값으로 주도 확정 문구를 만들지 않으며 모의 데이터는 명시한다. 순위는 시장 관심도이며 매수 신호가 아니다.

`qry_tp=4`는 별도 접힌 예약 영역으로만 둔다. 누적순위 수집·일일 결산 생성·교집합 생성·Calendar는 구현하지 않았다. `qry_tp=2/3/5`도 수집하지 않는다. 기존 정기 10회와 TOP20 시세 연동·DB 스키마는 변경하지 않는다.

HTML은 v2 CSS와 네이티브 details를 재사용하며 외부 스크립트·폰트·CDN 없이 작동한다. 기본 화면의 UUID·API 원본·검증 진단은 접힌 상세에 남는다. PC 1360×900에서는 핵심 요약과 미분류 안내를 함께 볼 수 있고 작은 화면은 세로 적층·표 내부 가로 스크롤을 사용한다.

```powershell
python -B -m unittest discover -s tests -p test_radar_v3.py -v
python -B -m unittest discover -s tests -v
git diff --check
```

v3 테스트는 별도 임시 DB와 가상 응답을 사용한다. 운영 DB를 테스트 fixture로 열거나 실제 API를 호출하지 않는다. 실행 검증 결과와 실제 데이터 HTML·화면 캡처는 로컬 `data/step4b-v3-*` 산출물에 보존한다.
