# C15-3 오전 동시 수집 최소 수정안

상태: 제안만 작성. 운영 코드·설정·DB 변경 및 실행 없음.

## 확인한 누락

- 운영 `schedule.py`는 0198 고정 10회 일정만 실행한다. 09:45는 없다.
- `--with-top20-quotes`는 ka10095 후속 시세이며 0186(ka10032)이 아니다.
- 운영 `turnover_rank.py`에는 plan/offline/live-test만 있으며 정기 일정 연결이 없다.
- 개발 브랜치에는 `schedule.collect_schedule(..., slots=..., after_slot=...)`와 `operating_workflow.Workflow.__call__`의 0186 저장 구현이 이미 있다. 새 수집 엔진은 필요 없다.

## 최소 변경 범위

1. 기존 일정에 09:45만 추가하여 09:40·09:45·09:50에 0198을 수집한다. 다른 슬롯은 유지한다.
2. 개발 코드의 기존 `after_slot` 확장을 재사용한다. 해당 세 슬롯에만 기존 `turnover_rank.LiveTransport`, `Profile('000','0','1')`, `collect()`를 호출하는 수집 전용 후처리를 연결한다. 전체 분석·차트·텔레그램 Workflow는 활성화하지 않는다.
3. 기존 token_manager 공유, 요청 간격, 예정시각 중복 방지와 기존 DB 보존 방식을 재사용한다. 0186 오류가 이미 저장된 0198 성공을 덮어쓰지 않게 한다.
4. 0186은 별도 `data/turnover/YYYY-MM-DD/0940.db`, `0945.db`, `0950.db`에 저장한다. 동일 슬롯 파일은 덮어쓰지 않는다. 개발 검증에서는 개발 폴더 하위 경로만 사용한다.
5. 두 API의 수신시각·환경·슬롯과 0186 페이지 종료 여부를 기존 회차 결과와 함께 남긴다. `max_pages=1`은 partial일 수 있으므로 전체 목록 성공으로 표시하지 않는다. 단위·오전 누적 범위 검증은 기존 분석 조건을 그대로 적용한다.

운영 반영과 실제 API 검증은 이번 작업 범위에 포함하지 않는다. 변경 후에도 동일 시점 데이터와 테마·종목 적격성 검증이 충족되어야 오전 보고를 생성할 수 있다.
