# C12-V / C12-X 실전 관측과 Telegram 연결

운영 stock1 폴더와 별도의 개발/실행 후보 폴더에서 검증한다. 기존 Collector,
Credentials, C13 TokenManager/DPAPI, Step 6-D, C12-K Bridge, C12-L 대시보드,
C14 renderer와 Telegram HTTP/전송 예약 엔진을 재사용한다.

## 불완전한 실전 관측

`arvis-observation-briefing-v1`은 검증된 C12 선정 결과가 없는 경우의 부분 보고다.
기존 C12 AM 보고서를 포함하고, 실제 단발 관측 순위·등락률·거래대금을 별도 표시한다.
관측 상위 5개를 C12 후보 Top5로 승격하지 않는다. 섹터/시총/반복 관측/단위·시각
근거가 부족하면 주도섹터·후보는 보류이며 Step 6-D/C14 상태도 미확인으로 표시한다.

보고서의 해시는 무결성 검사이며 독립적인 시장 검증이나 서명이 아니다.
`source_kind=readonly_adapter`, `environment=real`, `candidate_confirmed=false`를 유지한다.
0198의 시장 범위는 미검증이며 KRX는 0186 요청 조건이다.

## Telegram

기존 엔진은 실데이터 보고서도 미리보기/검증할 수 있지만 기본 실제 전송은 계속 차단한다.
사용자가 승인한 실전 전송에만 `--send --allow-readonly-report`를 함께 명시한다.
Windows native CA가 필요한 환경에서는 기존 세션 한정 어댑터를
`--windows-trust-store`로 사용한다. 전역 SSL 설정, verify=False, 재시도 추가는 없다.

기존 개인 채팅 allowlist, 비밀 검사, 4096 UTF-16 제한, 메시지와 보고서 일치,
전송 전 독점 예약 및 unknown 실패 뒤 예약 보존을 유지한다. 테스트는 text 1건만
전송하며 HTML/음성/자동 정기 발송을 포함하지 않는다.

`OBSERVATION_REVIEW` 예약은 날짜·환경·시장·대상으로 구분한다. 같은 날 입력을
다시 생성해도 중복 테스트를 차단한다. 오전 AM 선정 보고의 기존 예약과는 별도다.
다른 PC의 예약은 공유하지 않으므로 병원 PC를 실제 발송 주체로 고정해야 한다.

## 시간표와 운영 전환

기존 10회 프로필은 기본값으로 보존한다. C12-X 실행 후보는 같은 scheduler loop에
명시적 23회 프로필(09:10~09:55 매 5분, 10:00~16:00 매 30분)을 전달한다.
0186는 기존 LiveTransport/collect를 09:40/09:50/10:00/11:00/14:00/14:30/15:00/15:30에 연결한다.
첫 페이지 1회 예산을 유지하며 partial을 전체 시장으로 취급하지 않는다. 16:00 이후에는 다음 거래일까지 수집하지 않는다.

09:40/09:45/09:50은 한 AM 상태를 공유한다. 기존 C12 기준으로 최초 선정하면 1회 전송,
선정 코드 집합 또는 주도섹터가 바뀌면 중요 변경으로 처리한다. 가격 변화만으로 재발송하지 않는다.
자료 부족은 기존 선정을 취소하는 증거로 사용하지 않는다. 09:50까지 미선정이면 부족 자료 종료 보고만 보낸다.
갱신 전송은 이전 판의 sent 확인 및 실제 선정 서명 변경을 요구한다. reserved/unknown을 새 판으로 우회하지 않는다.

AM의 순위 반복 기준 슬롯(09:20/30/40/50)과 검증 정책은 변경하지 않는다. 새 09:45 관측을
기존 슬롯으로 이름 바꾸거나 반복 횟수로 더하지 않는다. 09:45는 최신 적격성/검증 근거로 기존 판단을 재검토하는 단계다.
현재 0186는 09:45에 추가 조회하지 않으므로 09:40 자료가 시각 정책에 맞지 않으면 거래대금은 보류한다.

14:30은 기존 Step 6-D 사전 검토, 15:00은 후보/부족 자료 텍스트 보고다. 종가 확인 조건을
만족하지 않으면 provisional이며 AM 정책을 오후까지 완화하지 않는다. 15:30/16:00은 관측과 기록만 한다.
16:00 자료를 확정 정규장 종가로 승격하지 않는다.

Step 7-A의 snapshot_from_review/analyze를 재사용하며 D0 anchor는 불변으로 보존한다.
선정·비교 종목과 일일 gzip 요약을 장기 보관하고, 검증된 거래일 달력/종가 이벤트가 없으면 D+1/D+2 결과는 미확인이다.
원본 10거래일 보존은 제안일 뿐 자동 삭제 코드는 활성화하지 않는다.

봇 설정은 기존 Configuration 환경변수 우선 로딩을 유지한다. 변수 세트가 없을 때만
%LOCALAPPDATA%/Stock1/credentials/telegram-config.dpapi를 기존 WindowsDPAPI로 복원한다.
부분 환경변수와 보호 파일을 섞지 않으며 평문 fallback/기존 파일 덮어쓰기는 없다.
텍스트만 사용하고 음성/문서를 생성·전송하지 않는다. 배포 간 예약은 기존 notification_state를 공유한다.

새 real 실행 후보의 기본 래퍼 실행은 ACL/Credentials 준비 검사만 한다.
명시적 `-Run`은 승인된 전환 창에서만 사용한다. 기존 scheduled Collector가 있으면
시작을 거부하고, 실제 엔진의 DB/environment 잠금과 scheduled_at 중복 제약도 유지한다.
원래 mock .env/DB는 덮어쓰지 않으며 별도 real DB와 DPAPI cache scope를 사용한다.

운영 전환 시 작업 XML을 백업하고 실제 프로세스 중지/새 작업 동작/복구 명령을
사용자에게 먼저 제시한다. 승인 전에는 기존 프로세스와 작업을 변경하지 않는다.
